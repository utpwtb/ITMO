# 报告编写规则

> 中文全译：[原文](https://github.com/secs-dev/os-course/blob/dee17bc418979ecbae3b45db74cdc1494bdc9bb1/doc/report.md)。

高质量的报告意味着：理解报告的目的，并采用便于检查的格式。

## 编写报告的目的

> [!IMPORTANT]
> 报告只应包含目标读者（教师）需要的重要信息，并且这些信息应当易于理解。

报告应使读者看到你工作的关键方面，而不是开发过程中所有可能的细节。因此，必须认真选择报告内容。

呈现信息时，应选择最容易理解的方式：

- 避免大量连续文本，包括大段源代码。
- 展示复杂而重要的关系时，优先使用图形元素，如表格、图表。

读者不应为了深入钻研主题而花费大量时间才能看懂报告。确有需要时，可以在报告正文或附录中补充更详细的文字描述。若需要放大段代码，也应放入附录，并从正文引用它。

## 报告格式

报告是按相关标准排版的 PDF 文件。

推荐使用文本标记语言制作报告，这样可以：

- 直接在协作开发平台（GitHub）的界面中方便地对内容发表评论。
- 通过模板保持不同文档的一致性。
- 将源文件编译为 PDF。

> [!TIP]
> 推荐使用 [Typst](https://typst.app/)：相较 LaTeX，它的语法更简单，也更接近熟悉的 Markdown。可以在在线服务中编写，也可以在本地仅用一个工具完成，不需要大量依赖。此外，已有符合 GOST 标准的 [Typst 文档模板](https://github.com/e1turin/typst-docs-template)。
