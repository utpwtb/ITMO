# 实验入门附图：中文说明

本文件翻译附图中的文字并解释含义，不保留原图文件。

## exp-variants.png / exp-variants.excalidraw.svg

两者是同一实验变体示意图的 PNG 与 Excalidraw SVG 版本。[原图](https://github.com/secs-dev/os-course/blob/dee17bc418979ecbae3b45db74cdc1494bdc9bb1/lab/intro-exp/img/exp-variants.excalidraw.svg)。

### 图中文字

| 原标签 | 中文 |
|---|---|
| Write / Read，w / r | 写入 / 读取 |
| Small / Large，s / l | 小数据 / 大数据 |
| Seqential / Random，seq / rand | 顺序 / 随机；图中 Seqential 是 Sequential 的拼写错误 |
| Cache / NoCache，c / nc | 使用缓存 / 不使用缓存 |
| case | 情形 |
| task | 任务 |
| scenario | 场景 |
| size | 大小 |
| faster / slower | 更快 / 更慢 |
| mutability | 是否修改数据（读/写维度） |
| locality | 局部性 |
| caching | 缓存方式 |

### 图中列出的七种比较

每行带 `/` 的维度是对照变量，其余条件保持一致。

| 图中配置 | 中文配置 | 对应研究问题 |
|---|---|---|
| `Read,Cache/NoCache,10M,Rand` | 读取，开/关缓存，10M，随机访问 | 缓存对扫描负载有多大影响？ |
| `Read,NoCache,10M,Seq/Rand` | 读取，无缓存，10M，顺序/随机访问 | 局部性对数据扫描重要吗？ |
| `Read/Write,Cache,10M,Rand` | 读/写，有缓存，10M，随机访问 | 常见场景中写入比读取重多少？ |
| `Write,Cache,500K/10M,Rand` | 写入，有缓存，500K/10M，随机访问 | 现代系统的典型场景中，数据大小重要吗？ |
| `Read/Write,Cache,10M,Seq` | 读/写，有缓存，10M，顺序访问 | 顺序处理场景中写入比读取重多少？ |
| `Write,Cache/NoCache,10M,Rand` | 写入，开/关缓存，10M，随机访问 | 缓存对修改负载有多大影响？ |
| `Write,NoCache,10M,Seq/Rand` | 写入，无缓存，10M，顺序/随机访问 | 局部性对数据修改重要吗？ |

这是原图对变体的解释。具体实验仍以教师分配参数和 [README](README.md) 为准，图中的数据规模和“更快/更慢”标签不是已经测得的通用结论。

## model.png

[原图](https://github.com/secs-dev/os-course/blob/dee17bc418979ecbae3b45db74cdc1494bdc9bb1/lab/intro-exp/img/model.png)分三层，从左到右为：

| 原标签 | 中文含义 |
|---|---|
| infologic | 信息逻辑层：图中的顶点与关系 |
| datalogic | 数据逻辑层：记录表及后继关系 |
| physical | 物理层：这些记录在实际文件中的位置 |
| Nº | 编号 |
| value | 值 |
| fallows | 后继指向；原图的英文拼写不规范 |
| header | 文件头 |

中间示意表的数据为：

| 编号 | 值 | 后继 |
|---|---:|---:|
| 1 | 11 | 3 |
| 2 | 67 | 5 |
| 3 | 48 | 4 |
| 4 | 17 | 2 |
| 5 | 52 | 0 |

沿链接可形成 `1 → 3 → 4 → 2 → 5 → 0` 的访问顺序；0 表示该示意链结束。物理图用 `0x0`、`0x10`、`0x20`、`0x40`、`0x50` 等位置说明：逻辑上相邻的记录在文件中不一定相邻，局部性由物理布局决定。

> 图是概念示意，不能把其中偏移直接当作当前源码的二进制格式。实际遍历程序的文件头长度是 40 字节，常见记录长度是 24 字节，应按源码读取。
