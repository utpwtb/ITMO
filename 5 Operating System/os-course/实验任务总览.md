## 1. intro-exp：性能实验方法入门

**要研究什么：**用图记录模拟文件数据访问，比较 `read/lseek` 与 `mmap` 的遍历时间。变体涉及读/写、缓存开/关、大小、顺序/随机访问。两种程序各测两个比较配置，总共四组；实际比较维度按教师变体选择。

**流程：**生成可复现数据 → 编译现成程序 → 采集系统信息和清理干扰 → 基线观察 → 明确假设 → 规划 N 与交错运行 → 保存全部原始数据 → 统计并绘图 → 换 mmap 重做 → 汇总四组。

**原文明确提交：**图生成脚本、两个采集脚本、四组原始数据、数据分析脚本/Notebook、报告。报告须解释环境、假设、N、缓存方法，并有四组比较表和图。

**答辩重点：**能重新运行脚本，解释环境决定、置信区间、N 的影响和图大小依据。

**特别注意：**`chain` 是随机物理顺序；顺序文件应使用 `sequential`。当前 mmap 的 `--no-cache` 只给 `MADV_RANDOM` 提示，仍使用页缓存。附带 PDF 的图形要求与 README 有少量差异，见 [PDF 差异补译](lab/intro-exp/PDF差异补译.md)。七种图示变体见[附图中文说明](lab/intro-exp/附图中文说明.md)。

## 2. vtsh：当前 Shell 实验

**基础功能：**提示符、按绝对路径启动程序、`cd` / `exit`、参数与环境传递、正确等待和状态处理。

**教师指定扩展：**管道 `|`、单命令后台 `&`、逻辑 `;` / `&&` / `||`、资源限制 NPROC/NOFILE/FSIZE/STACK/AS。它们不是每人全部必做。

**实现重点：**REPL、parser、executor、进程管理分工；正确使用创建进程、`exec`、`wait`，处理 EOF、信号、僵尸进程、管道关闭和短路执行。禁止用 `system`、`popen`、`/bin/sh -c` 代做 Shell。

**验证重点：**自己编写 Python 测试，覆盖基础功能和指定扩展；不能使用 `shell=True`。`vfork` 变体设置资源限制要按附录使用包装程序。

**交付重点：**代码、自己的测试和有结论的报告；这来自文中的开发/测试/报告步骤，不是额外模板。已有源码只打印 Hello, world!，不是完整 Shell。

## 3. vt25hell：另一版基础 Shell

**任务：**用 C 编写 Shell，启动带参数的程序，并输出运行耗时；根据变体支持一个控制运算符 `&&`、`||`、`;` 或 `&`。

**变体：**创建子进程使用 `fork`、`vfork`、`clone` 或 `clone3`；控制运算符也按教师指定。

**报告：**封面、所分配任务、全部自写代码清单、结论；答辩要演示工作效果并解释实现。

**与 vtsh 区别：**该 README 没有完整的 REPL/资源限制教程，布局为 `bin/` + `lib/`；当前 vtsh 是 `src/`，测试路径和构建细节也更新了。不能擅自将一种版本的全部要求移入另一种。

## 4. vtpc：用户态页缓存

**任务：**C 语言动态库实现块缓存；六 API 为打开、关闭、读取、写入、定位、同步。磁盘访问须绕过操作系统页缓存。

**变体：**教师指定 LRU、LFU、MRU、FIFO、NRU、Clock、Optimal、Random、Second chance、ARC、2Q、LRU-K 等置换策略。Optimal 要允许用户提供下次访问提示。

**性能要求：**改造教师指定的实验 1 负载程序，验证加缓存后正确，并比较前后性能。当前新版 vtsh 文档没有给出该负载的具体题目，需由教师确定。

**报告：**任务、简要代码说明、加缓存前后数据及分析结论。

**特别注意：**现成 `vtpc.c` 只是转发 libc，尚未实现缓存；CMake 目前写 STATIC，而任务要求动态库。实际 `vtpc_open` 头文件有三个参数；保持测试 API 兼容。

## 5. vtkm：内核结构信息查询

**任务：**编写用户态程序和可加载内核模块。用户以命令行参数指定目标，不能传内存地址；模块从系统表定位目标内核结构，返回信息，用户程序打印。

**教师指定：**通信接口（`syscall`、`ioctl`、`procfs`、`debugfs`）和目标结构。结构可由名称指定，也可由 `/proc` 文件间接指定，此时需推断底层结构。

**应完成的两端：**用户态请求/打印程序、内核态查找/响应模块。仓库只提供模块进入/退出模板，没有用户程序。

该 README 未单列专属报告/评分细则；应结合课程[提交流程](doc/process.md)和教师要求。

## 6. vtfs：内核文件系统

**任务：**实现 Linux 内核文件系统，先在 RAM 存数据，再实现远程服务器持久存储。

原文十阶段为：

1. 编译、加载、卸载简单内核模块。
2. 注册文件系统、挂载与填充 superblock。
3. 列出文件和目录。
4. 实现目录查找与导航。
5. 创建、删除文件。
6. 将写死内容替换为 RAM 中的数据结构。
7. 创建、删除目录。
8. 文件读取与写入（原文带 *）。
9. 普通文件硬链接（原文带 *）。
10. 自行实现远程文件系统服务器，采用持久存储，通过提供的 HTTP 客户端访问。

**报告与展示：**报告含仓库链接及结论，能按教师要求运行测试。服务端语言不限，可使用数据库。

**特别注意：**原文建议使用独立虚拟机。示例不是可直接复制的完整实现：根 inode 编号不统一、iterate 片段不完整、内核 API 需按版本更新。远程 API/token 的完整规则未给出。

## 8. corosched：协程反馈调度

**任务：**改进外部 [Coroed](https://github.com/vityaman-edu/coroed) 有栈协程框架的调度器。原先数组存任务，数量受限、调度不公平；改为 feedback 调度器。

**验证：**测试新调度器性质，并与原实现比较。

队列层数、时间片和优先级更新公式未在本仓库指定；应结合框架与教师要求确定。

## 9. corohttp：协程异步 HTTP

**任务：**为 Coroed 加入异步 I/O。操作应只挂起等待中的协程，线程继续运行其他就绪协程；对调用协程而言，读写接口仍像阻塞调用。

**技术选择：**研究 Linux 的 aio、epoll、io_uring，选适合的方案。注意 libc 线程局部变量与基于 alarm 的抢占机制可能交互。

**HTTP 接口：**请求 `/hello/<name>` 返回 `{"message":"<name>"}`。原文没有要求在 message 中加 Hello 前缀。

**对照：**另写一请求一线程的服务器，设计性能测试，与协程版本比较。

## 10. bpf-xdp：过滤、限速与 libbpf

**学习顺序：**最小 XDP_PASS 程序 → 编译/反汇编 → 手工 bpf 加载与测试 → network namespace/veth → 接口挂载 → verifier → IP 过滤 → 每 IP 限速 → libbpf。

**关键实现：**

- `load_xdp.c` 从文件读取、加载、测试并连接 XDP 程序。
- IPv4 过滤必须检查数据包边界，能够解释 verifier 诊断。
- 拒绝 `10.200.1.2`，并与 `10.200.1.3` 作对照演示。
- 每 IP 超过 5 包/秒就丢弃，向用户态提供每个 IP 的统计。
- 使用 maps；手工创建 map、处理 `ldimm64` 与重定位，可通过 argv 指定偏移，自动化是加分方向。
- 最后用 libbpf 重写限速器。

**理解要求：**对象文件信息、指令、JIT、verifier、maps、不同伪指令形式、静态/动态链接与重定位。

目录中仅有 README，示例中的程序文件需要自己创建。原文 `rpc`/`rps` 文件命名和部分示例输出不一致，译文已标明。
