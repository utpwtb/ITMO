## 一、Servlet、JSP、JSF 的总体定位

**中文：**

* **Servlet** 是 Java Web 的底层规范和 API，不是框架
* **JSP** 是建立在 Servlet 之上的视图模板技术，不是框架
* **JSF** 是建立在 Servlet 之上的完整 Web UI 框架

一句话总结：

> Servlet 是地基，JSP 是视图技术，JSF 是一套完整框架。

**Русский：**

* **Servlet** — это базовая спецификация и API Java Web, не фреймворк
* **JSP** — это технология шаблонов представления, построенная поверх Servlet, не фреймворк
* **JSF** — это полноценный Web UI фреймворк, построенный поверх Servlet

Кратко:

> Servlet — фундамент, JSP — представление, JSF — фреймворк.

---

## 二、Servlet：为什么它不是框架

**中文：**
Servlet 解决的是最基础的 HTTP 问题：

* 请求与响应处理
* 组件生命周期管理

它只提供：

* 规范（Specification）
* 编程接口（API）

Servlet 不具备框架特征：

* 没有控制反转（IoC）
* 不规定 MVC 结构
* 不管理 UI、表单或校验

结论：

> Servlet 是构建框架的底层材料，而不是框架本身。

**Русский：**
Servlet решает базовые задачи:

* обработка HTTP-запросов и ответов
* управление жизненным циклом компонентов

Он предоставляет только:

* спецификацию
* API

Servlet не является фреймворком, потому что:

* нет IoC
* нет архитектурных ограничений
* нет управления UI и валидацией

Вывод:

> Servlet — это строительный материал для фреймворков, а не сам фреймворк.

---

## 三、JSP：为什么它也不是框架

**中文：**
JSP 的本质是：

> 一种会被编译成 Servlet 的页面模板技术。

JSP 的职责：

* 输出 HTML
* 使用 EL / JSTL 进行简单逻辑
* 充当 MVC 中的 View 层

JSP 不负责：

* 请求流程控制
* 页面状态管理
* 组件或事件模型

结论：

> JSP 永远只是视图技术，而不是框架。

**Русский：**
По своей сути JSP:

> это шаблон страницы, который компилируется в Servlet.

Назначение JSP:

* генерация HTML
* простая логика через EL и JSTL
* уровень View в MVC

JSP не управляет:

* потоком запросов
* состоянием страницы
* событиями или компонентами

Вывод:

> JSP — это только технология представления, а не фреймворк.

---

## 四、JSF：为什么它是框架

**中文：**
JSF 提供了一整套框架级能力：

* 统一请求入口（Front Controller）
* 组件树模型
* 生命周期管理
* 事件驱动模型
* 表单处理、校验与转换
* 视图状态保存与恢复

核心特征：

> 应用运行在 JSF 之内，而不是直接控制流程。

**Русский：**
JSF предоставляет полноценную инфраструктуру:

* единый вход (Front Controller)
* модель дерева компонентов
* управление жизненным циклом
* событийную модель
* обработку форм, валидацию и конвертацию
* сохранение и восстановление состояния

Ключевая идея:

> Приложение работает внутри JSF, а не управляет им напрямую.

---

## 五、JSF 的技术本质

**中文：**
从实现角度看：

* JSF 运行在 Servlet 容器中
* 由 `FacesServlet` 作为核心控制器
* 开发者几乎不直接使用 Servlet API

从架构角度看：

> JSF 是组件化、事件驱动、有状态的 Web UI 框架。

**Русский：**
С точки зрения реализации:

* JSF работает в Servlet-контейнере
* управляется `FacesServlet`
* разработчик почти не взаимодействует с Servlet API

С архитектурной точки зрения:

> JSF — компонентный, событийный и состояниесохраняющий Web UI фреймворк.

---

## 六、Servlet、JSP 与 JSF 的关系

**中文：**
三者可以理解为分层和包裹关系：

```
Servlet 容器
 └── Servlet API
      ├── JSP（模板 → Servlet）
      └── JSF
            ├── FacesServlet
            ├── 生命周期
            ├── 组件模型
            └── Facelets
```

**Русский：**
Их отношения можно представить так:

```
Servlet-контейнер
 └── Servlet API
      ├── JSP → Servlet
      └── JSF
            ├── FacesServlet
            ├── жизненный цикл
            ├── модель компонентов
            └── Facelets
```

---

## 七、为什么 JSF 使用 Facelets，而不是 JSP

**中文：**

* JSP 是“请求时执行”的模板，不适合组件树构建
* 与 JSF 生命周期不匹配
* 官方已淘汰 JSF + JSP

Facelets：

* 为 JSF 专门设计
* 基于 XHTML
* 完美支持组件树与模板复用

结论：

> 现代 JSF 应用只使用 Facelets，不使用 JSP。

**Русский：**

* JSP выполняется во время запроса и плохо совместим с JSF
* не подходит для построения дерева компонентов
* связка JSF + JSP устарела

Facelets:

* специально разработан для JSF
* основан на XHTML
* полностью поддерживает шаблоны и повторное использование

Вывод:

> Современные JSF-приложения используют только Facelets.

---

## 八、最终总结

**中文：**

| 技术    | 定位           | 是否框架 |
| ------- | -------------- | -------- |
| Servlet | 底层规范 / API | 否       |
| JSP     | 视图模板技术   | 否       |
| JSF     | Web UI 框架    | 是       |

**Русский：**

| Технология | Роль                   | Фреймворк |
| -------------------- | -------------------------- | ------------------ |
| Servlet              | Базовый API         | Нет             |
| JSP                  | Представление | Нет             |
| JSF                  | Web UI фреймворк  | Да               |
