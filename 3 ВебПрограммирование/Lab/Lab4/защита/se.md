### 1.Платформа Java EE. Спецификации и их реализации.

Java EE平台是一套基于Java语言的企业级应用开发标准规范集合，包含Servlet、JSP、EJB、JPA等核心组件规范。这些规范由Oracle（现移交Eclipse基金会，称为Jakarta EE）制定，并由第三方供应商提供具体实现，例如Apache Tomcat实现Web容器规范，WildFly、IBM WebSphere提供完整Java EE服务器实现。开发者依据规范编写代码，确保应用程序可在不同兼容服务器间移植部署。

Платформа Java EE — это набор стандартных спецификаций для разработки корпоративных приложений на языке Java, включающих основные компоненты, такие как Servlet, JSP, EJB, JPA. Эти спецификации разработаны Oracle (в настоящее время переданы фонду Eclipse и называются Jakarta EE) и реализуются сторонними поставщиками. Например, Apache Tomcat реализует спецификации веб-контейнера, а WildFly и IBM WebSphere предоставляют полные реализации серверов Java EE. Разработчики пишут код в соответствии со спецификациями, что обеспечивает переносимость приложений между различными совместимыми серверами.

### 2.Принципы IoC, CDI и Location Transpanency. Компоненты и контейнеры.

1. **IoC（控制反转）** ：将对象的创建和依赖管理交给容器处理，开发者无需手动实例化，降低代码耦合度。
2. **CDI（上下文依赖注入）** ：Java EE规范，通过注解（如 `@Inject`）自动管理组件间的依赖关系和生命周期。
   - RMI
     RMI 是 Java 的远程方法调用。它允许一个 Java 虚拟机上的对象调用另一个虚拟机（通常在网络上的另一台机器）上对象的方法，就像调用本地对象一样。
     RMI 是实现位置透明性的经典技术。
     核心机制：客户端调用的是一个看起来像本地对象的存根（Stub），这个存根会通过网络将调用请求转发给真实的远程对象，并将结果返回。客户端代码无需知道这个对象实际是在本地还是在千里之外。

关系总结：RMI 提供了位置透明性的技术实现。开发者可以专注于业务逻辑（“调用哪个对象的方法”），而无需操心底层的网络通信、数据序列化等复杂细节。RMI 容器和框架将“位置”这一物理信息隐藏了起来。

**位置透明性（Location Transparency）** ：分布式环境中，客户端调用远程组件时无需关注其物理位置（如网络地址），由容器透明处理通信细节。

**组件与容器** ：组件（如Servlet、EJB）是封装业务逻辑的单元；容器（如Web容器、EJB容器）提供运行时环境，负责组件的生命周期、资源管理和服务支持。

**组件** 是可复用的软件模块（例如 JavaBeans、Enterprise JavaBeans、Servlet），它们实现特定的业务逻辑或功能，设计用于在 **容器** 中运行。

**容器** 是运行时环境（例如应用服务器、Web 容器），它为组件提供必要的服务：生命周期管理、安全性、事务处理、分布式计算等。容器负责创建组件实例并管理它们的运行。

**IoC（Инверсия управления）** ：Создание объектов и управление зависимостями делегируется контейнеру, что снижает связанность кода.

**CDI（Контекстно-зависимое внедрение）** ：Стандарт Java EE, управляет зависимостями и жизненным циклом компонентов через аннотации (например, `@Inject`).

- RMI
  RMI — это удалённый вызов методов в Java. Он позволяет объекту на одной виртуальной машине Java вызывать методы объекта на другой машине (через сеть), как если бы это был локальный объект.

  Связь RMI с прозрачностью местоположения
  RMI — это классическая технология, реализующая прозрачность местоположения.

  Механизм: клиент вызывает заглушку (Stub), которая выглядит как локальный объект. Эта заглушка передаёт вызов по сети реальному удалённому объекту и возвращает результат. Клиенту не нужно знать, находится ли объект локально или удалённо.

  Итог связи: RMI обеспечивает техническую реализацию прозрачности местоположения. Разработчик сосредотачивается на логике («какой метод вызвать»), а не на сетевых деталях. RMI-контейнер скрывает физическое «местоположение».

**Прозрачность местоположения（Location Transparency）** ：В распределённой среде клиенты вызывают удалённые компоненты без указания их физического размещения — контейнер обрабатывает коммуникацию автоматически.

**Компоненты и контейнеры** ：Компоненты (например, Servlet, EJB) инкапсулируют бизнес-логику; контейнеры (веб-контейнер, EJB-контейнер) обеспечивают их выполнение, управление жизненным циклом и ресурсами.

**Компоненты** — это повторно используемые программные модули (например, JavaBeans, Enterprise JavaBeans, сервлеты), которые реализуют конкретную бизнес-логику или функциональность. Они разрабатываются для работы внутри  **контейнеров** .

**Контейнеры** — это среда выполнения (например, сервер приложений, веб-контейнер), которая предоставляет компонентам необходимые сервисы: управление жизненным циклом, безопасность, транзакции, распределённые вычисления. Контейнер создаёт экземпляры компонентов и управляет их работой.

### 3.Управление жизненным циклом компонентов. Дескрипторы развёртывания.

1. **生命周期管理**：容器负责组件（如Servlet、EJB）的创建、初始化、运行和销毁，通过回调方法（如 `@PostConstruct`、`@PreDestroy`）让开发者介入关键阶段。
2. **部署描述符**：XML或注解配置文件（如 `web.xml`、`ejb-jar.xml`），声明组件结构、依赖、安全及事务规则，实现配置与代码分离。

---

1. **Управление жизненным циклом**：Контейнер управляет созданием, инициализацией, работой и уничтожением компонентов (например, Servlet, EJB), позволяя разработчику вмешиваться через методы обратного вызова (например, `@PostConstruct`, `@PreDestroy`).
2. **Дескрипторы развёртывания**：Конфигурационные файлы в XML или аннотациях (например, `web.xml`, `ejb-jar.xml`), объявляющие структуру компонентов, зависимости, безопасность и транзакции, отделяя конфигурацию от кода.

好的，这里以Java EE中最典型的两种组件为例，用最核心的阶段来说明它们的生命周期，以及**容器**在其中扮演的绝对主导角色。

**核心思想：托管生命周期**
组件的生命周期**完全由容器管理**，而非开发者。开发者可以通过特定的回调方法（如注解 `@PostConstruct`, `@PreDestroy`）在生命周期的关键节点“注入”自己的逻辑。

---

**1. Servlet 生命周期（在Web容器中）**

这是一个**请求驱动**的生命周期，主要分为三个阶段：

* **初始化**

  * **触发**：Web应用启动时或首个请求到达时。
  * **容器行动**：容器加载Servlet类，调用其无参构造函数创建实例，然后调用 `init()` 方法（或标记了 `@PostConstruct` 的方法）进行一次性初始化（如加载资源）。
  * **状态**：Servlet进入“已就绪”状态。
* **服务**

  * **触发**：每次HTTP请求映射到该Servlet时。
  * **容器行动**：容器为每个请求创建一个新线程，并调用Servlet的 `service()` 方法。该方法会根据请求类型（GET, POST等）自动路由到 `doGet()`, `doPost()` 等具体方法。
  * **状态**：这是Servlet的主要工作状态，处理业务逻辑。
* **销毁**

  * **触发**：Web应用停止或重新加载时。
  * **容器行动**：容器调用 `destroy()` 方法（或标记了 `@PreDestroy` 的方法），让Servlet有机会清理资源（如关闭数据库连接）。
  * **状态**：Servlet实例被垃圾回收。

**生命周期图：**
`加载类 -> 构造实例 -> init() (@PostConstruct) -> [ 循环：service() -> doGet()/doPost()... ] -> destroy() (@PreDestroy)`

---

**2. EJB（如无状态会话Bean）生命周期（在EJB容器中）**

这是一个**池化管理**的生命周期，更注重实例的复用。

* **不存在状态**

  * 开始时，Bean实例不存在。
* **创建与依赖注入**

  * **触发**：客户端首次请求或容器初始化时。
  * **容器行动**：容器创建Bean实例，然后**自动注入**所有它声明的依赖（如通过 `@EJB`, `@Inject` 注解标记的其他Bean或资源）。这是**IoC/CDI**的体现。
  * **回调**：容器调用 `@PostConstruct` 方法，执行自定义初始化。
* **就绪/在池中状态**

  * Bean实例进入一个“就绪实例池”。
  * 当客户端调用其业务方法时，容器从池中取出一个实例为其服务。服务完成后，实例**通常被放回池中**，而非销毁，以供下一个请求复用。这是高效处理并发的基础。
* **销毁**

  * **触发**：应用停止或容器需要缩减池规模时。
  * **容器行动**：容器调用 `@PreDestroy` 方法，让Bean清理资源，然后实例被销毁。

**生命周期图：**
`不存在 -> 容器创建实例 -> 依赖注入 -> @PostConstruct -> 进入就绪池 -> [循环：客户端调用 -> 执行业务方法 -> 返回池中] -> @PreDestroy -> 销毁`

---

**总结**

* **管理者**：**容器**是生命周期的绝对导演。
* **开发者介入点**：通过标准化的**生命周期回调方法**（`@PostConstruct`, `@PreDestroy`, `init()`, `destroy()`）。
* **模式不同**：
  * **Servlet** 生命周期与**HTTP请求**紧密绑定。
  * **EJB** 生命周期与**实例池**和**依赖注入**紧密绑定，强调资源复用和松耦合。
* **共同目标**：通过托管生命周期，让开发者从复杂的对象管理、资源管理和线程管理中解放出来，专注于业务逻辑。

### 4.Java EE API. Виды компонентов. Профили платформы Java EE.

1. **Java EE API**：一套标准接口与规范（如Servlet、JPA、EJB API），用于开发企业应用，确保跨服务器兼容性。
2. **组件种类**：
   - Web组件（Servlet、JSP、JSF）处理Web层。
   - 业务组件（EJB）封装核心逻辑。
   - 连接器组件（JCA）集成外部系统。
3. **平台配置**：
   - **Full Profile**：完整功能（如EJB、JMS），适用于传统企业应用。
   - **Web Profile**：轻量级子集（仅Servlet、JSP等Web技术），适用于Web应用。

---

1. **Java EE API**：Стандартные интерфейсы и спецификации (например, Servlet, JPA, EJB API) для разработки корпоративных приложений с гарантией совместимости между серверами.
2. **Виды компонентов**：
   - Веб-компоненты (Servlet, JSP, JSF) для веб-уровня.
   - Бизнес-компоненты (EJB) для основной логики.
   - Коннекторы (JCA) для интеграции внешних систем.
3. **Профили платформы**：
   - **Full Profile**：Полный набор функций (EJB, JMS) для традиционных корпоративных приложений.
   - **Web Profile**：Облегчённая версия (только Servlet, JSP) для веб-приложений.

---

好的，我们直接看三种核心Java EE组件最本质的区别。

**1. Web组件**

* **代表**：Servlet、JSP、JSF
* **核心职责**：**处理HTTP请求与响应**，构建用户界面。
* **运行环境**：**Web容器**（如Tomcat）。
* **关键特征**：
  * **请求/响应模型**：生命周期由HTTP请求驱动。
  * **主要生成HTML**：直接或通过模板生成网页内容。
  * **典型用途**：控制器、视图、RESTful API端点。

**2. 业务组件**

* **代表**：EJB（尤其是会话Bean）
* **核心职责**：**封装核心业务逻辑**，提供事务、安全等企业级服务。
* **运行环境**：**EJB容器**（存在于如WildFly、WebLogic等全功能服务器中）。
* **关键特征**：
  * **声明式服务**：通过注解即可获得**容器管理的事务、安全性、并发控制**（如 `@TransactionAttribute`）。
  * **远程访问**：支持远程调用（RMI）。
  * **典型用途**：订单处理、用户管理、复杂的计算服务。

**3. 连接器组件**

* **代表**：JCA资源适配器
* **核心职责**：**实现Java EE应用与外部企业信息系统（EIS）的连接桥梁**。
* **运行环境**：**应用服务器**的**连接器容器**。
* **关键特征**：
  * **连接非Java系统**：专用于连接数据库、ERP（如SAP）、消息队列（如MQ）、遗留系统等。
  * **管理连接池、事务和安全**：提供标准方式管理与EIS的连接，并支持跨资源的事务。
  * **典型用途**：让Java EE应用可以安全、高效地调用SAP的函数或访问特定的数据库驱动。

---

1. **Веб-компоненты**
   Представители: Servlet, JSP, JSF

Основная задача: Обработка HTTP-запросов и ответов, построение пользовательского интерфейса.

Среда выполнения: Веб-контейнер (например, Tomcat).

Ключевые особенности:

Модель «запрос/ответ»: Их жизненный цикл управляется HTTP-запросами.

Генерация HTML: Прямо или через шаблоны создают содержимое веб-страниц.

Типичное использование: Контроллеры, представления (View), конечные точки RESTful API.

2. **Бизнес-компоненты**
   Представители: EJB (особенно Session Bean)

Основная задача: Инкапсуляция ключевой бизнес-логики, предоставление корпоративных сервисов, таких как транзакции и безопасность.

Среда выполнения: EJB-контейнер (присутствует в полнофункциональных серверах, таких как WildFly, WebLogic).

Ключевые особенности:

Декларативные сервисы: Получают управляемые контейнером транзакции, безопасность, контроль параллелизма через аннотации (например, @TransactionAttribute).

Удалённый доступ: Поддерживают удалённый вызов (RMI).

Типичное использование: Обработка заказов, управление пользователями, сложные вычислительные сервисы.

3. **Компоненты-коннекторы**
   Представители: JCA Resource Adapter (ресурсный адаптер)

Основная задача: Служить мостом для подключения приложения Java EE к внешним корпоративным информационным системам.

Среда выполнения: Контейнер коннекторов в сервере приложений.

Ключевые особенности:

Подключение к не-Java системам: Специально созданы для подключения к базам данных, ERP (например, SAP), очередям сообщений (например, MQ), унаследованным системам.

Управление пулами соединений, транзакциями и безопасностью: Предоставляют стандартный способ управления соединениями с EIS и поддерживают распределённые транзакции.

Типичное использование: Позволяют приложению Java EE безопасно и эффективно вызывать функции SAP или использовать специфические драйверы баз данных.

### 5.Компоненты EJB. Stateless & Stateful Session Beans. EJB Lite и EJB Full.

1. **EJB组件类型**：主要包括会话Bean、消息驱动Bean和实体Bean（已被JPA取代）。会话Bean分为无状态和有状态两种。
2. **无状态 vs 有状态会话Bean**：
   - **无状态**：不保存客户端状态，所有实例等价，适合高频通用业务（如计算服务）。
   - **有状态**：维护客户端会话状态，绑定特定客户端，适合多步骤交互（如购物车）。
3. **EJB Lite 与 EJB Full**：
   - **EJB Lite**：轻量子集（仅含会话Bean、容器管理事务、拦截器等），适用于Web Profile。
   - **EJB Full**：完整规范（增加消息驱动Bean、远程调用、定时器等），需Full Profile服务器支持。

---

1. **Типы компонентов EJB**：Основные — Session Bean, Message-Driven Bean и Entity Bean (заменён JPA). Session Bean делится на Stateless и Stateful.
2. **Stateless vs Stateful Session Bean**：
   - **Stateless**：Не хранит состояние клиента, все экземпляры эквивалентны, подходит для частых операций (например, расчёты).
   - **Stateful**：Сохраняет состояние сессии клиента, привязан к конкретному клиенту, подходит для многошаговых процессов (например, корзина покупок).
3. **EJB Lite и EJB Full**：
   - **EJB Lite**：Упрощённая версия (только Session Bean, управляемые транзакции, перехватчики), для Web Profile.
   - **EJB Full**：Полная спецификация (добавляет Message-Driven Bean, удалённый вызов, таймеры), требует Full Profile сервера.

### 6.Работа с электронной почтой в Java EE. JavaMail API.

Java EE 通过 **JavaMail API** 提供电子邮件支持。

- **核心功能**：发送和接收电子邮件（SMTP/POP3/IMAP），支持附件、HTML内容和身份验证。
- **配置方式**：通过 `Session` 对象连接邮件服务器（在 `web.xml` 或服务器配置中设置主机、端口等参数）。
- **使用场景**：用户注册确认、通知推送、报表发送等异步通信。

---

Java EE предоставляет поддержку электронной почты через **JavaMail API**.

- **Основные функции**：Отправка и получение email (SMTP/POP3/IMAP), поддержка вложений, HTML-контента и аутентификации.
- **Конфигурация**：Подключение к почтовому серверу через объект `Session` (параметры хоста, порта и др. задаются в `web.xml` или настройках сервера).
- **Применение**：Подтверждение регистрации, уведомления, рассылка отчётов и другая асинхронная коммуникация.

---

**核心类与主要方法**

JavaMail 的核心是几个关键类，它们像一个发送邮件的流水线：

1. **`Session`**：

   * **作用**：邮件会话，包含连接邮件服务器所需的所有配置信息（如SMTP服务器地址、端口、认证信息）。
   * **主要方法**：
     * `Session.getInstance(Properties props, Authenticator auth)`：创建邮件会话。
     * `getTransport()`：获取传输对象。
2. **`MimeMessage`**：

   * **作用**：代表一封具体的电子邮件。可以设置发件人、收件人、主题、正文、附件等所有内容。
   * **主要方法**：
     * `setFrom(Address address)`：设置发件人。
     * `setRecipients(Message.RecipientType type, Address addresses)`：设置收件人（`TO`）、抄送（`CC`）、密送（`BCC`）。
     * `setSubject(String subject)`：设置主题。
     * `setText(String text)`：设置纯文本正文。
     * `setContent(Object content, String type)`：设置复杂内容（如HTML正文）。
     * `saveChanges()`：保存邮件更改。
3. **`Transport`**：

   * **作用**：负责将邮件发送到服务器。
   * **主要方法**：
     * `connect(String host, String user, String password)`：连接到SMTP服务器。
     * `sendMessage(Message message, Address[] addresses)`：发送邮件。
     * `close()`：关闭连接。

**例子**

```java
import javax.mail.*;
import javax.mail.internet.*;
import java.util.Properties;

public class SimpleEmailSender {
    public static void main(String[] args) throws MessagingException {
        // 1. 配置连接参数
        Properties props = new Properties();
        props.put("mail.smtp.host", "smtp.gmail.com"); // SMTP服务器地址
        props.put("mail.smtp.port", "587");            // 端口（TLS）
        props.put("mail.smtp.auth", "true");           // 需要认证
        props.put("mail.smtp.starttls.enable", "true");// 启用TLS加密

        // 2. 创建会话（使用认证器）
        Session session = Session.getInstance(props, new Authenticator() {
            protected PasswordAuthentication getPasswordAuthentication() {
                return new PasswordAuthentication("your-email@gmail.com", "your-app-password"); // 邮箱和授权码
            }
        });

        // 3. 创建邮件对象
        Message message = new MimeMessage(session);
        message.setFrom(new InternetAddress("your-email@gmail.com"));
        message.setRecipients(Message.RecipientType.TO,
                InternetAddress.parse("recipient@example.com")); // 收件人
        message.setSubject("测试邮件主题");
        message.setText("这是一封测试邮件的正文内容。");

        // 4. 发送邮件
        Transport.send(message);

        System.out.println("邮件发送成功！");
    }
}
```

**关键点说明**

1. **认证**：现代邮箱（如Gmail、QQ）通常需要使用**授权码**而非登录密码进行SMTP认证。
2. **加密**：`mail.smtp.starttls.enable` 是必需的，用于加密连接，保障安全。
3. **依赖**：需要将 JavaMail API 的 JAR 包（如 `javax.mail.jar`）添加到项目类路径中。
4. **进阶**：发送 HTML、添加附件等，需要使用 `MimeMultipart` 和 `MimeBodyPart` 类来构建复杂的邮件结构。

### 7.JMS. Реализация очередей сообщений. Способы доставки сообщений до клиента. Message-Driven Beans.

1. **JMS**：Java消息服务API，用于在应用间**异步可靠**地发送消息。
2. **消息队列实现**：
   - **点对点**：队列模型，消息由单个消费者消费。
   - **发布/订阅**：主题模型，消息广播给所有订阅者。
3. **消息传递方式**：
   - **同步**：客户端主动接收（`receive()`）。
   - **异步**：客户端注册消息监听器（`MessageListener`），消息自动推送。
4. **消息驱动Bean**：一种特殊EJB，作为JMS的**异步消费者**，由容器管理生命周期和并发，自动触发 `onMessage()`方法处理消息。

---

1. **JMS**：API Java Message Service для **асинхронной и надежной** передачи сообщений между приложениями.
2. **Реализация очередей**：
   - **Point-to-Point**：Модель очереди, сообщение потребляется одним получателем.
   - **Publish/Subscribe**：Модель топика, сообщение рассылается всем подписчикам.
3. **Способы доставки**：
   - **Синхронный**：Клиент активно получает (`receive()`).
   - **Асинхронный**：Клиент регистрирует слушатель (`MessageListener`), сообщения доставляются автоматически.
4. **Message-Driven Bean**：Специальный EJB, являющийся **асинхронным потребителем** JMS, управляется контейнером; метод `onMessage()` автоматически вызывается для обработки сообщений.

### 8.Понятие транзакции. Управление транзакциями в Java EE. JTA.

**事务管理** 是确保一系列数据库（或其他资源）操作作为一个**不可分割的原子单元**执行的机制，其核心目标是维护数据的**ACID**特性。
**事务概念**：一组操作作为不可分割的原子单元，要么全部成功（提交），要么全部失败回滚，保证数据ACID特性（原子性、一致性、隔离性、持久性）。

**核心概念（ACID）**

* **原子性**：事务中的所有操作要么**全部成功**（提交），要么**全部失败**（回滚）。
* **一致性**：事务使数据从一个**有效状态**转换到另一个有效状态（遵循业务规则）。
* **隔离性**：并发事务的执行**互不干扰**（如通过锁机制）。
* **持久性**：一旦事务提交，其结果**永久保存**（即使系统故障）。

**在Java EE中的实现方式**
Java EE 提供了两种标准的事务管理模型：

1. **容器管理事务**

   * **控制者**：应用服务器容器。
   * **方式**：**声明式**（开发者通过注解配置事务行为）。
   * **特点**：业务代码与事务代码解耦，简单安全，适用于大多数场景。
   * **示例**：在 EJB 方法上添加 `@TransactionAttribute(REQUIRED)`。
2. **Bean管理事务**

   * **控制者**：开发者。
   * **方式**：**编程式**（开发者手动编写事务控制代码）。
   * **特点**：灵活性高，可精确控制事务边界，但代码复杂易错。
   * **示例**：通过 `UserTransaction` 接口手动调用 `begin()`, `commit()`, `rollback()`。

**关键技术：JTA**

* Java 事务 API，是 Java EE 分布式事务的标准接口。
* 支持跨多个资源管理器（如数据库、消息队列）的**全局事务**，确保跨系统的操作原子性。

---

**Управление транзакциями** — это механизм, гарантирующий выполнение набора операций (например, с базой данных) как **неделимой атомарной единицы**, чья основная цель — сохранение свойств **ACID**.
**Понятие транзакции**：Набор операций как неделимая атомарная единица — либо все успешно выполняются (коммит), либо откатываются, гарантируя свойства ACID.

**Ключевые принципы (ACID)**

* **Атомарность**: Все операции в транзакции либо **полностью выполняются** (фиксируются), либо **полностью отменяются** (откатываются).
* **Согласованность**: Транзакция переводит данные из одного **корректного состояния** в другое (соблюдая бизнес-правила).
* **Изолированность**: Параллельные транзакции **не мешают** друг другу (например, через блокировки).
* **Долговечность**: После фиксации транзакции её результат **сохраняется навсегда** (даже при сбое системы).

**В Java EE реализуется через две модели**

1. **Транзакции, управляемые контейнером**

   * **Контроль**: Контейнер сервера приложений.
   * **Способ**: **Декларативный** (настройка поведения через аннотации).
   * **Пример**: Добавление `@TransactionAttribute(REQUIRED)` к методу EJB.
2. **Транзакции, управляемые бином**

   * **Контроль**: Разработчик.
   * **Способ**: **Программный** (ручное управление в коде).
   * **Пример**: Использование интерфейса `UserTransaction` для вызовов `begin()`, `commit()`, `rollback()`.

**Ключевая технология: JTA**

* Стандартный API для распределённых транзакций в Java EE.
* Поддерживает **глобальные транзакции** между несколькими ресурсами (базы данных, очереди сообщений), обеспечивая атомарность операций в распределённой системе.

### 9.Веб-сервисы. Технологии JAX-RS и JAX-WS.

- **Веб-сервисы**：基于网络的标准化服务接口，允许不同系统通过互联网进行数据交换和功能调用。
- **JAX-WS**：基于SOAP协议的Web服务技术，使用XML格式和WSDL契约，适合需要严格事务和安全保障的企业级集成。
- **JAX-RS**：基于REST架构的Web服务技术，使用HTTP方法和JSON/XML格式，适合轻量级、高性能的Web API和移动后端。
  - JAX-RS是 Jakarta EE 平台中用于构建 RESTful Web 服务的框架。
  - **主要特点**：
    基于注解开发；
    自动处理数据的序列化与反序列化（如JSON ↔ Java对象）；
    与 CDI Bean 兼容；
    自动处理HTTP协议细节；
    底层由应用服务器实现。

JAX-RS框架：基于注解的RESTful服务开发框架，自动处理HTTP序列化/反序列化。

工作原理：客户端请求 → 服务器容器处理 → JAX-RS资源响应。

核心注解：@Path定义URL，HTTP方法注解定义操作，@Produces/@Consumes定义数据格式。

参数绑定：通过注解提取路径、查询参数、请求头等数据。

全局配置：使用@ApplicationPath设置API根路径。

```java
@ApplicationPath(«/api»)
public class MyApplication extends Application {}
```

---

- **Веб-сервисы**：Стандартизированные сетевые интерфейсы для обмена данными между разными системами через интернет.
- **JAX-WS**：Технология веб-сервисов на основе SOAP, использует XML и WSDL, подходит для корпоративной интеграции с гарантиями транзакций и безопасности.
- **JAX-RS**：Технология RESTful веб-сервисов, использует HTTP-методы и JSON/XML, оптимальна для легковесных Web API и мобильных бэкендов.
  - Фреймворк для построения RESTful веб-сервисов на базе Jakarta EE.
  - **Ключевые особенности**:
    Основан на аннотациях;
    Автоматическая сериализация и десериализация данных;
    Совместим с CDI beans;
    Забирает на себя «рутину» по работе с HTTP;
    «Под капотом» реализуется все еще на сервлетах.

Фреймворк JAX-RS：Фреймворк для RESTful-сервисов на аннотациях с автоматической сериализацией HTTP.

Принцип работы：Запрос клиента → обработка контейнером → ответ ресурса JAX-RS.

Ключевые аннотации：@Path для URL, HTTP-аннотации для операций, @Produces/@Consumes для форматов данных.

Извлечение параметров：Аннотации для получения данных из пути, запроса, заголовков.

Глобальная настройка：@ApplicationPath задаёт корневой путь API.

### 10. Платформа Spring. Сходства и отличия с Java EE. | Spring 与 Java EE 对比

- Сходства: Оба решают задачи корпоративного уровня, поддерживают IoC, DI, транзакции, работу с БД и безопасность.
- Отличия:

  - Java EE — это стандарт, требующий сервера приложений.
  - Spring — это фреймворк, который может работать в простом контейнере сервлетов (Tomcat) или как автономное приложение (Spring Boot).
  - Spring часто считается более гибким и модульным.

对比： Java EE 是官方标准，Spring 是事实上的行业标准。Spring 更加轻量且无需复杂的服务容器。

### 11. Модули Spring. Архитектура Spring Runtime. Spring Security и Spring Data. | Spring 模块、架构、Security 与 Data

- Spring Runtime: Архитектура состоит из Core Container (Beans, Core, Context), AOP (Aspects), Data Access (JDBC, ORM), Web (MVC).
- Spring Security: Модуль для обеспечения аутентификации (кто вы?) и авторизации (что вам можно?). Защищает методы и URL-адреса.
- Spring Data: Упрощает доступ к данным. Позволяет создавать репозитории (интерфейсы), для которых Spring сам генерирует реализацию (например, JpaRepository).

Spring 模块： Spring Security 负责安全，Spring Data 简化了数据库访问逻辑（DAO 层）。

### 12. Реализация IoC и CDI в Spring. Сходства и отличия с Java EE. | Spring 中的 IoC 与 CDI

- Spring IoC: Реализуется через ApplicationContext. Объекты называются Beans.
- Способы внедрения: @Autowired (аналог @Inject в Java EE), @Resource.
- Отличия: Spring предлагает более мощную систему конфигурации (Java Config, XML, аннотации) и поддержку условий (@Conditional), чего в классическом CDI меньше.

依赖注入对比： Spring 使用 @Autowired，Java EE 使用 @Inject。Spring 的配置方式更多元。

### 13. Реализация REST API в Java EE и Spring. | REST API 实现对比

- Java EE (JAX-RS): Использует аннотации @Path, @GET, @Produces. Пример: Jersey, RestEasy.
- Spring (Spring MVC / Boot): Использует аннотацию @RestController. Методы помечаются @GetMapping, @PostMapping. Включает встроенную поддержку Jackson для JSON.

REST 实现： Java EE 常用 @Path，Spring 使用 @RestController 和 @RequestMapping。

### 14.React JS. Архитектура и основные принципы разработки приложений.

**Архитектура（架构）**React采用**组件化架构**，核心是：

1. **虚拟DOM**：内存中的DOM轻量副本，通过Diff算法高效更新界面
2. **JSX语法**：JavaScript + HTML混合语法，直观描述UI
3. **单向数据流**：数据只能通过props从父组件流向子组件，事件通过回调反向通信
4. **声明式UI**：描述“UI应该是什么样子”，而非“如何一步步构建UI”

**Принципы разработки（开发原则）**

1. **组件复用原则**：每个组件独立、可重用，单一职责
2. **状态提升原则**：共享状态放在最近的共同父组件
3. **组合优于继承**：通过组合简单组件构建复杂功能
4. **纯函数原则**：组件应像纯函数，相同props始终渲染相同UI
5. **关注点分离**：容器组件处理逻辑，展示组件负责渲染

**简单比喻**：React像一个**乐高积木系统**：

- 架构 = 积木的标准化接口和连接方式（虚拟DOM是设计图，JSX是说明书）
- 原则 = 拼装规则（复用积木、从下往上拼、相同积木拼出相同结构）

---

**Архитектура**React использует **компонентную архитектуру**, основанную на:

1. **Виртуальный DOM**: Легковесная копия DOM в памяти, эффективно обновляет интерфейс через Diff-алгоритм
2. **JSX синтаксис**: Смесь JavaScript + HTML для интуитивного описания UI
3. **Однонаправленный поток данных**: Данные передаются только через props от родителя к потомку, события — через callback-функции
4. **Декларативный UI**: Описание «как UI должен выглядеть», а не «как его построить шаг за шагом»

**Принципы разработки**

1. **Повторное использование компонентов**: Каждый компонент независим, переиспользуем, имеет одну ответственность
2. **Подъём состояния**: Общее состояние хранится в ближайшем общем родителе
3. **Композиция вместо наследования**: Сложные функции строятся из простых компонентов
4. **Принцип чистых функций**: Компоненты как чистые функции — одинаковые props дают одинаковый рендер
5. **Разделение ответственности**: Контейнерные компоненты для логики, презентационные — для отображения

### 15.Компоненты React. State & props. "Умные" и "глупые" компоненты.

- Props: Входные данные, которые передаются компоненту извне (только для чтения).
- State: Внутренние данные компонента, которые могут меняться со временем (вызывают рендер).
- Умные компоненты (Smart/Container): Отвечают за логику, запросы к API и хранение состояния.
- Глупые компоненты (Dumb/Presentational): Только отображают данные, полученные через props, и не имеют своей логики.

**React组件**
React应用的基本构建块，分为**函数组件**和**类组件**两种形式。

**State & Props**

- **Props（属性）**：父组件传给子组件的**只读数据**（像函数的参数）
- **State（状态）**：组件内部管理的**可变数据**（像组件的私有记忆）

**"智能"与"傻瓜"组件**

- **"智能"组件**：负责逻辑和状态管理，知道"如何工作"
- **"傻瓜"组件**：只负责UI展示，知道"如何显示"

**关系总结**：

```
智能组件（有State） → 传递Props → 傻瓜组件（无State）
    （业务逻辑）                     （纯UI展示）
```

---

**Компоненты React**
Базовые строительные блоки React-приложений, существуют в двух формах: **функциональные компоненты** и **классовые компоненты**.

**State & Props**

- **Props（свойства）**：**Данные только для чтения**, передаваемые от родительского компонента дочернему（как параметры функции）
- **State（состояние）**：**Изменяемые данные**, управляемые внутри компонента（как частная память компонента）

**"Умные" и "глупые" компоненты**

- **"Умные" компоненты**：Отвечают за логику и управление состоянием, знают "как работает"
- **"Глупые" компоненты**：Отвечают только за отображение UI, знают "как выглядит"

**Сводка отношений**：

```
Умные компоненты（есть State） → Передают Props → Глупые компоненты（нет State）
      （бизнес-логика）                     （чистое UI-отображение）
```

### 16.Разметка страниц в React-приложениях. JSX.

**React中的页面标记**
React使用 **JSX** 进行页面标记，它是 **JavaScript的语法扩展**，允许在JS代码中直接编写类似HTML的结构。

**JSX核心特点**

- **混合JavaScript和HTML**：`const element = <h1>Hello, {name}</h1>`
- **编译为JavaScript**：JSX最终被Babel编译为 `React.createElement()`调用
- **必须闭合标签**：单标签如 `<img />`必须自闭合
- **className代替class**：因class是JS保留字
- **内联样式用对象**：`style={{color: 'red'}}`（双花括号）

**JSX优势**

- 更直观的UI描述
- 类型安全（配合TypeScript）
- 编译时错误检查

---

**Разметка страниц в React**
React использует **JSX** для разметки — это **синтаксическое расширение JavaScript**, позволяющее писать HTML-подобную структуру прямо в JS-коде.

**Ключевые особенности JSX**

- **Смешивание JavaScript и HTML**：`const element = <h1>Привет, {name}</h1>`
- **Компиляция в JavaScript**：JSX компилируется Babel в вызовы `React.createElement()`
- **Обязательное закрытие тегов**：Одиночные теги как `<img />` должны самозакрываться
- **className вместо class**：потому что class — зарезервированное слово в JS
- **Встроенные стили как объект**：`style={{color: 'red'}}`（двойные фигурные скобки）

**Преимущества JSX**

- Более интуитивное описание UI
- Типобезопасность（с TypeScript）
- Проверка ошибок при компиляции

### 17.Навигация в React-приложениях. ReactRouter.

**React应用导航**
React本身是单页应用（SPA），**React Router** 是实现客户端路由的标准库。

**React Router核心功能**

- **声明式路由**：使用组件定义路由
- **动态路由匹配**：`/users/:id` 匹配不同ID
- **嵌套路由**：父/子路由结构
- **编程式导航**：`useNavigate()` hook跳转
- **路由守卫**：权限控制（如登录验证）

**基本用法**

```jsx
// 1. 定义路由
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />
</Routes>

// 2. 导航链接
<Link to="/about">关于</Link>

// 3. 编程导航
const navigate = useNavigate();
navigate('/about');
```

---

**Навигация в React-приложениях**
React — это одностраничное приложение（SPA），**React Router** — стандартная библиотека для клиентской маршрутизации。

**Основные возможности React Router**

- **Декларативная маршрутизация**：Определение маршрутов через компоненты
- **Динамическое сопоставление**：`/users/:id`匹配不同的 ID
- **Вложенные маршруты**：Иерархия родительских/дочерних маршрутов
- **Программная навигация**：Переход через hook `useNavigate()`
- **Защита маршрутов**：Контроль доступа（например, проверка авторизации）

**Базовое использование**

```jsx
// 1. Определение маршрутов
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />
</Routes>

// 2. Навигационные ссылки
<Link to="/about">О нас</Link>

// 3. Программная навигация
const navigate = useNavigate();
navigate('/about');
```

### 18.Управление состоянием интерфейса. Redux.

**界面状态管理**
在复杂React应用中，多个组件需要共享和同步状态，Redux提供了一个**集中式的状态管理方案**。

**Redux核心概念**

1. **Store（仓库）**：唯一的状态存储中心
2. **Action（动作）**：描述状态变更的普通对象
3. **Reducer（归约器）**：纯函数，根据Action更新状态
4. **单向数据流**：`View → Action → Reducer → Store → View`

**Redux三原则**

1. **单一数据源**：整个应用只有一个Store
2. **状态只读**：只能通过Action修改状态
3. **纯函数修改**：Reducer必须是纯函数

---

**Управление состоянием интерфейса**
В сложных React-приложениях множеству компонентов нужно совместно использовать и синхронизировать состояние. Redux предоставляет **централизованное решение для управления состоянием**.

**Ключевые концепции Redux**

1. **Store（хранилище）**：Единственный центральный источник состояния
2. **Action（действие）**：Обычный объект, описывающий изменение состояния
3. **Reducer（редуктор）**：Чистая функция, обновляющая состояние на основе Action
4. **Однонаправленный поток данных**：`View → Action → Reducer → Store → View`

**Три принципа Redux**

1. **Единственный источник истины**：Все приложение имеет один Store
2. **Состояние только для чтения**：Изменение только через Action
3. **Изменение через чистые функции**：Reducer должен быть чистой функцией

### 19.Angular: архитектура и основные принципы разработки приложений.

**Angular架构**
Angular是一个**基于TypeScript的完整前端框架**，采用组件化架构：

**核心架构特点**

1. **模块化**：应用由NgModule组织
2. **组件化**：UI由树形组件构成
3. **依赖注入**：内置IoC容器管理服务
4. **双向数据绑定**：模板与组件数据自动同步
5. **TypeScript支持**：强类型、面向对象

**开发原则**

1. **约定优于配置**：框架提供标准化结构
2. **关注点分离**：组件、服务、模板职责清晰
3. **单向数据流**（默认）+ 双向绑定（可选）
4. **响应式编程**：RxJS集成

---

**Архитектура Angular**
Angular — это **полноценный фронтенд-фреймворк на TypeScript** с компонентной архитектурой:

**Ключевые архитектурные особенности**

1. **Модульность**：Приложение организовано через NgModule
2. **Компонентность**：UI строится как дерево компонентов
3. **Внедрение зависимостей**：Встроенный IoC-контейнер для управления сервисами
4. **Двусторонняя привязка данных**：Автоматическая синхронизация шаблона и данных компонента
5. **Поддержка TypeScript**：Строгая типизация, ООП

**Принципы разработки**

1. **Соглашения вместо конфигураций**：Фреймворк предоставляет стандартную структуру
2. **Разделение ответственности**：Чёткое разделение компонентов, сервисов, шаблонов
3. **Однонаправленный поток данных**（по умолчанию）+ двусторонняя привязка（опционально）
4. **Реактивное программирование**：Интеграция с RxJS

### 20.Angular: модули, компоненты, сервисы и DI.

**1. 模块（Modules）**

- 应用的组织单元，用 `@NgModule`装饰器声明
- 包含：组件、服务、指令、管道等
- 根模块：`AppModule`（应用入口）
- 功能模块：按功能划分（如 `UserModule`）

**2. 组件（Components）**

- UI构建块，包含：
  - 模板（HTML + Angular模板语法）
  - 样式（CSS/SCSS）
  - 类逻辑（TypeScript）
- 使用 `@Component`装饰器定义
- 构成组件树（父子关系）

**3. 服务（Services）**

- 业务逻辑和数据访问层
- 使用 `@Injectable`装饰器
- 职责：API调用、数据共享、工具函数
- 通过依赖注入使用

**4. 依赖注入（DI）**

- Angular的核心设计模式
- 自动创建和管理服务实例
- 通过构造函数注入
- 提高可测试性和模块化

---

**1. Модули（Modules）**

- Организационные единицы приложения，объявляются через `@NgModule`
- Содержат：компоненты，сервисы，директивы，пайпы
- Корневой модуль：`AppModule`（входная точка）
- Функциональные модули：разделение по функциям（например, `UserModule`）

**2. Компоненты（Components）**

- Строительные блоки UI，включают：
  - Шаблон（HTML + синтаксис Angular）
  - Стили（CSS/SCSS）
  - Логику класса（TypeScript）
- Определяются декоратором `@Component`
- Образуют дерево компонентов（родительско-дочерние отношения）

**3. Сервисы（Services）**

- Уровень бизнес-логики и доступа к данным
- Используют декоратор `@Injectable`
- Ответственность：вызовы API，обмен данными，вспомогательные функции
- Используются через внедрение зависимостей

**4. Внедрение зависимостей（DI）**

- Ключевой шаблон проектирования Angular
- Автоматическое создание и управление экземплярами сервисов
- Внедрение через конструктор
- Повышает тестируемость и модульность

### 21.Angular: шаблоны страниц, жизненный цикл компонентов, подключение CSS.

**1. 页面模板**

- **Angular模板语法**：HTML + 指令（`*ngIf`, `*ngFor`）+ 插值（`{{data}}`）
- **数据绑定**：
  - 插值：`<p>{{title}}</p>`
  - 属性绑定：`<img [src]="imageUrl">`
  - 事件绑定：`<button (click)="onClick()">`
  - 双向绑定：`<input [(ngModel)]="name">`

**2. 组件生命周期**
**主要生命周期钩子**：

- `ngOnChanges()`：输入属性变化时
- `ngOnInit()`：组件初始化（只执行一次）
- `ngDoCheck()`：变更检测时
- `ngAfterViewInit()`：视图初始化后
- `ngOnDestroy()`：组件销毁前

**3. CSS连接方式**

- **组件样式**：`@Component({ styleUrls: ['./app.component.css'] })`
- **全局样式**：`angular.json`中配置
- **样式封装**：`ViewEncapsulation`（Emulated/None/ShadowDom）
- **CSS预处理**：支持SCSS、SASS、LESS

---

**1. Шаблоны страниц**

- **Синтаксис шаблонов Angular**：HTML + директивы（`*ngIf`, `*ngFor`）+ интерполяция（`{{data}}`）
- **Привязка данных**：
  - Интерполяция：`<p>{{title}}</p>`
  - Привязка свойств：`<img [src]="imageUrl">`
  - Привязка событий：`<button (click)="onClick()">`
  - Двусторонняя привязка：`<input [(ngModel)]="name">`

**2. Жизненный цикл компонентов**
**Основные хуки жизненного цикла**：

- `ngOnChanges()`：при изменении входных свойств
- `ngOnInit()`：инициализация компонента（один раз）
- `ngDoCheck()`：при проверке изменений
- `ngAfterViewInit()`：после инициализации представления
- `ngOnDestroy()`：перед уничтожением компонента

**3. Подключение CSS**

- **Стили компонентов**：`@Component({ styleUrls: ['./app.component.css'] })`
- **Глобальные стили**：конфигурация в `angular.json`
- **Инкапсуляция стилей**：`ViewEncapsulation`（Emulated/None/ShadowDom）
- **CSS-препроцессоры**：поддержка SCSS、SASS、LESS

### 22.Angular: клиент-серверное взаимодействие, создание, отправка и валидация данных форм.

- **错误状态显示**：`formControl.errors`、CSS类

**Шаги отправки формы**：

3. Обработка ответа сервера

- **Встроенные валидаторы**：required, minLength, pattern и др.
- **Пользовательские валидаторы**：создание функций валидации
