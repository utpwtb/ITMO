Здравствуйте. Сегодня я покажу скрипт для сбора данных о чемпионах League of Legends. Эти данные нужны для будущего графа знаний. Например, мы хотим находить магов, которые могут защищать союзников щитом и ограничивать движение противника. Класс чемпиона даёт общую информацию, а конкретные эффекты описаны в тексте умений. На этом этапе подготовлены данные. Сам граф будет следующим шагом.

Основной источник здесь называется Data Dragon. Он предоставляет официальные JSON-файлы с именами, классами, характеристиками и умениями чемпионов. Скрипт использует стандартную библиотеку Python. Для этих открытых файлов ключ API не нужен. Дополнительные данные берутся из CommunityDragon и с официального сайта. Они сохраняются отдельно. У сайта нет гарантии исторической версии, поэтому его страницы используются для сверки описаний, а не для замены основных данных.

Эта функция фиксирует версию игры в отдельном файле. При следующем запуске скрипт использует тот же выбор. Это помогает не смешивать описания из разных обновлений. В нашем наборе выбрана версия шестнадцать точка двадцать точка один и русская локализация. Для CommunityDragon также проверяется номер патча. Здесь показана команда для трёх чемпионов. Параметры включают дополнительные источники и загрузку значков. Для сбора всех чемпионов достаточно убрать ограничение по именам.

Здесь исходные данные приводятся к единой структуре. Для чемпиона сохраняются идентификатор, имя, классы и характеристики. Для каждого основного умения создаётся отдельная запись с обозначением P, Q, W, E или R. Например, запись с идентификатором Lux:Q связана с чемпионом Lux. Скрипт сохраняет исходный HTML и текст без тегов. У записи остаются версия и адрес источника. Классы Mage и Support обозначают тип чемпиона, а не позицию на карте.

Теперь рассмотрим Люкс. В данных у неё указаны классы мага и поддержки. В описании Q сказано, что умение наносит урон и обездвиживает до двух врагов. У W есть подробное описание щита для союзников. Здесь важно сохранить условие: жезл должен коснуться союзника. Поэтому для будущей связи в графе нужны сам эффект, его цель и условие действия. Этот пример подходит к исходному вопросу о защите союзников и контроле противника. Сейчас мы видим текстовые основания; готовый автоматический поиск по графу ещё предстоит реализовать.

В полном наборе собраны сто семьдесят три чемпиона и восемьсот шестьдесят пять записей основных умений. Каждый дополнительный источник также охватывает всех чемпионов. В этом файле указаны количество записей, версия и отсутствие ошибок. Для исходных файлов сохраняются адрес, время получения и контрольная сумма. При повторном запуске скрипт проверяет кеш и использует сохранённые файлы. При временной сетевой ошибке запрос повторяется. Результаты доступны в JSON для программы и в CSV для просмотра таблиц.

Эта таблица предназначена для ручной проверки механик. Пока здесь сохранены описания, а поля эффекта, цели и условия нужно заполнить. При повторном сборе ручные правки сохраняются. В подробных описаниях встречаются переменные в фигурных скобках. Если значение неизвестно, скрипт сохраняет переменную без догадок. Дополнительные формы умений тоже могут потребовать проверки. Следующий этап включает разметку механик и построение связей между чемпионами, классами и умениями. После этого можно будет выполнять поиск и объяснять результат конкретными описаниями. Спасибо.
