## 5. 统一案例：大学图书馆

在 `_meta/统一案例设定.md` 中维护唯一的案例设定。先写它，再写各讲中的教学改编例子。

### 5.1 初始设定与扩展方式

- 整个案例明确标注“虚构教学数据”。不使用现有 LoL 项目，不把虚构统计描述为实际效果。
- 采用稳定命名空间，例如 `https://example.org/kg-course/library/`，统一前缀 `lib:`。实体 ID、类名、属性名与中文标签集中登记。
- 起始范围包括作品、版本、馆藏副本、作者、读者、学科、图书馆等；后续逐步加入借阅事件、采购、来源记录。
- 清楚区分作品、版本和实物副本，说明 ISBN 对应版本层面的建模选择。使用教学标识时说明其性质和验证规则。
- 第一批示例只取读者能看懂的小子集；扩展采用增加数据和概念的方式。已有实体身份、关系方向和语义不随章节任意改变。
- 多元关系用明确的事件或关系节点建模，例如借阅事件关联读者、副本和时间；避免为了讲某个算法临时改变整个本体。
- 如果需要纠正早期案例，记录变更理由、受影响文件，并同步修正示例和预期输出。

### 5.2 各阶段用途

| 阶段 | 同一主题下的实践 |
|---|---|
| L01–L02 | 把图书、作者和主题表示为图；建立类与属性；比较显式事实、推理结果及未知事实。 |
| L03 | 查询某主题图书、作者作品、可借阅副本；使用过滤、可选属性、聚合和路径查询。 |
| L04 | 记录目录来源、时间和限定信息；用 SHACL/ShEx 检查缺失属性或错误类型。 |
| L05 | 将两个虚构图书馆的异构目录映射到统一模型，说明实体对齐与映射的区别。 |
| L06 | 从原始图投影出作者合作网络或主题网络，说明节点、边、方向、权重及投影规则。 |
| L07 | 选择明确关系做链接预测；定义正负例、训练与测试划分及评分含义。 |
| L08 | 在同一数据语境中解释特征、关系类型、消息传递和新实体推断。 |
| Extra1 | 用采购、馆藏关系展示属性图和企业图数据库操作。 |
| Extra2 | 在一个很小的作者合作子图上说明社区划分、模块度及 Ising/QUBO 映射。 |
| Extra3 | 用预约—借出—归还事件日志介绍流程发现、循环、并发和质量评价。 |

教材原例仍需解释清楚；增加统一主题例子时注明“教学改编”。三份 Extra 的原始案例可作课程内容讲解，不必伪装成图书馆原始材料。

### 5.3 数据与算法纪律

- 查询例子同时给出所需数据和预期结果；明确结果顺序是否有保证。
- 区分 OWL 推理与 SHACL 数据校验，也区分逻辑蕴含与统计预测。
- 图投影、无向化、采样、特征生成等转换均写出规则，不把转换后的图与原始 RDF 图混为一谈。
- 嵌入/GNN 的手算示例说明数字是人为指定还是训练所得；微型教学数据的指标只说明计算方法，不宣称模型性能。
- 链接预测避免把测试事实直接放入训练输入；说明负例构造与开放世界下“未观察到不等于为假”的区别。

以下为基本骨架，按实际教学内容细分。没有对应内容的模块可说明不适用，不编造定理或证明。

> 先修：链接到需要掌握的知识点

## 核心知识点

### 某个概念 / Русский термин / English term
来源：[PDF 名称 · PDF 第 n–m 页](实际链接)

**定义：** 如讲义给出俄文定义，准确摘录并给中文翻译。
**解释：** 动机、含义、适用条件，以及与已学知识的连接。
**公式或语法：** 给出必要形式，解释各符号、类型或张量维度。
**例子：** 教材原例的解读；必要时增加统一图书馆案例。

## 重要结论、算法或推导

|---|---|---|---|

解释标准：

1. 对核心概念给出“问题→定义→机制→例子→边界”，不把关键词清单当成完成。
2. 公式解释每个新符号及必要维度；重要推导不省略导致初学者无法衔接的中间步骤。
3. Turtle/SPARQL/SHACL 解释新增语法及其语义；算法说明输入、关键步骤和输出，不仅贴代码。
4. 俄文原始定义只在材料确实存在时按原文引用；材料为英文时保留相应英文。自行整理的俄语表述标为译写，避免伪称原文。
5. 解释以中文为主，英文缩写、俄文术语用于对照；无需每句话重复三语。
6. 不设硬性字数目标。通用定义链接到主要讲次，当前讲保留足够上下文，避免知识缺口或无意义重复。

## 7. 来源、补充、勘误与图像核对

- 所有输入 PDF 按页读取。建立覆盖表时逐页登记去向；连续同主题页可以合并为一个页段。
- 先提取文字，再对图表、公式、截图、提取缺失或乱码页做视觉核对。QML 材料逐页查看图像，不能按提取字数判断内容多少。
- 每个主要知识点的来源链接放在相应小节；原图与关键公式的页码应能准确定位。
- 原课件重复页合并为一次完整解释，覆盖表写明所涵盖页段；封面、广告、纯链接页等可以标“非教学内容”，不能悄悄跳过实质页面。
- 补充内容使用“补充解释”提示；必要时查询标准、官方文档、论文等一手来源，并记录实际访问日期和支持该说明的链接。
- 疑似错误先看完整页面和上下文，再核实。采用“讲义原述→核实依据→修正或解释”的方式；没有充分证据就标“待核实”。
- 历史标准、产品能力和数据规模按讲义语境呈现；涉及当前可运行工具或最新能力时核查当前资料，清楚区分课程版本与后续变化。
- 尚未核实的关键公式、事实或代码不能作为可靠结论使用。进度中登记位置、影响及后续核查方式。

## 8. 实践与验证的执行范围

| 类别 | 最低教学交付 | 验证要求 |
|---|---|---|
| RDF/OWL/SPARQL/SHACL | 必要数据、查询/约束/操作步骤、预期结果。OWL 说明推理器及启用规则。 | 在可用环境实际解析和运行；不能运行的明确标注，提供复现方法。 |
| 图论、PageRank、链接预测 | 小图、关键数值、逐步计算；代表性方法给最小脚本。 | 核对手算与程序结果；采用容差时解释原因。 |
| 嵌入、GNN | 评分函数、输入与输出维度、小型数值例子；代表性方法有最小代码。 | 手算或程序验证关键一步；不要求完整复现每篇论文、训练所有模型。 |
| SAP、量子计算及其他平台专题 | 解释原理、给清晰操作/伪代码或本地可用示例。 | 如无服务或硬件，标为未在该平台运行；不虚构平台输出，也不要求购买云资源。 |
| 自测 | 每篇主讲及 Extra 3–5 题，附折叠答案和解释。 | 检查题目能由本讲及注明先修回答，答案与正文一致。 |

共用可运行数据放 `examples/`，正文包含理解所需的小片段和链接。需要依赖时记录工具版本、运行命令及关键输出；采用适度依赖，不把整理笔记扩大成完整软件项目。

验证记录区分：已执行并得到结果、已手算核对、仅静态检查、未验证。不能把“代码看起来合理”记录为运行成功。未执行部分如影响当前讲的核心结论，保持该讲待核实状态。
