## 1. 软件开发方法论 / Методологии разработки ПО

### 瀑布模型 / Каскадная модель (Waterfall)

**中文：** 线性顺序模型，每个阶段必须完成后才能进入下一阶段。适用于需求明确、变更少的项目。

**Русский:** Линейная последовательная модель, где каждый этап должен быть завершён перед началом следующего. Подходит для проектов с чёткими требованиями и минимальными изменениями.

**阶段 / Этапы:**

1. 需求分析 / Анализ требований
2. 系统设计 / Проектирование системы
3. 编码实现 / Реализация (кодирование)
4. 测试 / Тестирование
5. 部署维护 / Развёртывание и поддержка

### 敏捷开发 / Гибкая разработка (Agile)

**中文：** 迭代增量式开发，强调快速响应变化、持续交付价值。包括Scrum、Kanban、XP等方法。

**Русский:** Итеративно-инкрементальная разработка с акцентом на быстрое реагирование на изменения и непрерывную поставку ценности. Включает Scrum, Kanban, XP и др.

### 螺旋模型 / Спиральная модель

**中文：** 结合瀑布模型的系统性和原型模型的迭代性，强调风险分析。适合大型复杂项目。

**Русский:** Сочетает систематичность каскадной модели и итеративность прототипирования с акцентом на анализ рисков. Подходит для крупных сложных проектов.

## 2. 统一过程 / Унифицированный процесс (RUP/UP)

**中文：** Rational Unified Process (RUP) 是一种迭代的、以架构为中心的、用例驱动的软件开发过程。

**Русский:** Rational Unified Process (RUP) — это итеративный, архитектурно-ориентированный и управляемый прецедентами процесс разработки ПО.

### 核心特征 / Ключевые характеристики:

| 特征 / Характеристика                                          | 说明 / Описание                                                                                                                                           |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **迭代开发 / Итеративная разработка**             | 项目分为多个迭代周期，每个迭代产生可执行的增量 / Проект делится на итерации, каждая даёт работающий инкремент |
| **用例驱动 / Управляемый прецедентами**         | 用例是需求捕获和系统设计的基础 / Прецеденты — основа для сбора требований и проектирования                      |
| **架构中心 / Архитектурно-ориентированный** | 早期建立架构基线，指导后续开发 / Ранняя установка архитектурного базиса                                                        |

### 四个阶段 / Четыре фазы:

```
起始阶段 (Inception) / Начальная фаза
    ↓
细化阶段 (Elaboration) / Фаза уточнения
    ↓
构建阶段 (Construction) / Фаза построения
    ↓
移交阶段 (Transition) / Фаза внедрения
```

### 核心工作流 / Основные рабочие потоки:

- **工程工作流 / Инженерные потоки:** 业务建模、需求、分析设计、实现、测试 / Моделирование бизнеса, требования, анализ и проектирование, реализация, тестирование
- **支持工作流 / Вспомогательные потоки:** 配置管理、项目管理、环境 / Управление конфигурацией, управление проектом, среда

## 3. 需求及其分类 / Требования и их категоризация

### 功能性需求 / Функциональные требования (FR)

**中文：** 描述系统必须提供的功能和服务，即"系统应该做什么"。

**Русский:** Описывают функции и услуги, которые система должна предоставлять — «что система должна делать».

**示例 / Примеры:**

- 用户可以登录系统 / Пользователь может войти в систему
- 系统应生成月度报表 / Система должна генерировать ежемесячные отчёты

### 非功能性需求 / Нефункциональные требования (NFR)

**中文：** 描述系统如何运行，约束功能性需求的实现方式。

**Русский:** Описывают, как система должна работать, накладывая ограничения на реализацию функциональных требований.

| 类别 / Категория                                      | 说明 / Описание                                                                         | 示例 / Примеры                                                                                            |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **性能 / Производительность**          | 响应时间、吞吐量 / Время отклика, пропускная способность       | 页面加载<2秒 / Загрузка страницы < 2 сек                                                      |
| **可靠性 / Надёжность**                        | 可用性、容错性 / Доступность, отказоустойчивость                   | 系统可用性99.9% / Доступность 99.9%                                                                   |
| **安全性 / Безопасность**                    | 认证、授权、加密 / Аутентификация, авторизация, шифрование   | 密码必须加密存储 / Пароли хранятся в зашифрованном виде                          |
| **可用性 / Удобство использования** | 易学习、易操作 / Лёгкость обучения, простота использования | 新用户5分钟内完成注册 / Новый пользователь регистрируется за 5 минут       |
| **可维护性 / Сопровождаемость**          | 代码可读性、模块化 / Читаемость кода, модульность                      | 代码注释覆盖率>30% / Покрытие комментариями > 30%                                           |
| **可扩展性 / Масштабируемость**          | 处理增长的能力 / Способность обрабатывать рост                       | 支持并发用户从1000到10000 / Поддержка 1000→10000 одновременных пользователей |

### 业务需求 / Бизнес-требования

**中文：** 从组织或客户角度描述高层次目标和期望。

**Русский:** Высокоуровневые цели и ожидания с точки зрения организации или заказчика.

### 用户需求 / Пользовательские требования

**中文：** 描述用户需要系统完成的任务和目标。

**Русский:** Описывают задачи и цели, которые пользователи хотят достичь с помощью системы.

### 系统需求 / Системные требования

**中文：** 对系统功能和约束的详细技术描述。

**Русский:** Детальное техническое описание функций и ограничений системы.

## 4. 需求属性 / Атрибуты требований

### 需求属性表 / Таблица атрибутов требований:

| 属性 / Атрибут                                | 说明 / Описание                                                   | 示例 / Примеры                                     |
| ---------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------- |
| **唯一标识 / Уникальный ID**         | 需求编号，便于追踪 / Номер для отслеживания           | REQ-001, UC-101                                           |
| **描述 / Описание**                    | 需求的详细说明 / Детальное описание требования | "系统应支持用户通过邮箱找回密码"                          |
| **优先级 / Приоритет**                | MoSCoW分类 / Классификация MoSCoW                            | Must have, Should have, Could have, Won't have            |
| **来源 / Источник**                    | 需求提出者 / Кто запросил                                      | 客户A, 市场部, 法规要求                                   |
| **稳定性 / Стабильность**          | 变更可能性 / Вероятность изменения                    | 高/中/低稳定 / высокая/средняя/низкая |
| **风险 / Риск**                            | 实现风险等级 / Уровень риска реализации             | 高/中/低 / высокий/средний/низкий     |
| **工作量 / Трудоёмкость**          | 估计实现时间 / Оценка времени реализации           | 8人时 / 8 человеко-часов                     |
| **验收标准 / Критерии приёмки** | 如何验证需求 / Как проверить выполнение             | 测试用例、性能指标                                        |
| **版本 / Версия**                        | 需求变更历史 / История изменений                          | v1.0, v1.1                                                |
| **状态 / Статус**                        | 当前状态 / Текущее состояние                              | 草稿/已批准/已实现/已验证                                 |

### MoSCoW优先级方法 / Метод приоритизации MoSCoW:

```
Must have (必须有) / Обязательно
    ↓ 没有这些系统无法运行
    Без этого система не работает
  
Should have (应该有) / Желательно
    ↓ 重要但可暂时省略
    Важно, но можно отложить
  
Could have (可以有) / Возможно
    ↓ 有则更好，无亦可
    Хорошо иметь, но не критично
  
Won't have (暂不会有) / Не сейчас
    ↓ 明确排除或推迟
    Явно исключено или отложено
```

## 5. UML语言 / Язык UML

**中文：** Unified Modeling Language (统一建模语言) 是用于软件系统可视化、规范、构建和文档化的标准图形化语言。

**Русский:** Unified Modeling Language — стандартизированный графический язык для визуализации, спецификации, конструирования и документирования программных систем.

### UML图分类 / Классификация диаграмм UML:

```
UML 2.x 图表 (14种 / 14 типов)
├── 结构图 / Структурные диаграммы (6种)
│   ├── 类图 / Диаграмма классов (Class)
│   ├── 组件图 / Диаграмма компонентов (Component)
│   ├── 部署图 / Диаграмма развёртывания (Deployment)
│   ├── 对象图 / Диаграмма объектов (Object)
│   ├── 包图 / Диаграмма пакетов (Package)
│   └── 组合结构图 / Диаграмма составных структур (Composite Structure)
│
└── 行为图 / Поведенческие диаграммы (8种)
    ├── 用例图 / Диаграмма прецедентов (Use Case) ⭐
    ├── 活动图 / Диаграмма деятельности (Activity)
    ├── 状态机图 / Диаграмма состояний (State Machine)
    ├── 序列图 / Диаграмма последовательности (Sequence)
    ├── 通信图 / Диаграмма коммуникации (Communication)
    ├── 定时图 / Диаграмма временных ограничений (Timing)
    ├── 交互概览图 / Диаграмма обзора взаимодействия (Interaction Overview)
    └── 制品图 / Диаграмма артефактов (Artifact)
```

### UML核心元素 / Основные элементы UML:

- **事物 / Сущности (Things):** 结构事物、行为事物、分组事物、注释事物
- **关系 / Отношения (Relationships):** 依赖、关联、泛化、实现
- **图 / Диаграммы (Diagrams):** 上述14种图

## 6. 用例与用例图 / Прецеденты использования и UseCase-диаграммы

### 用例定义 / Определение прецедента:

**中文：** 用例描述系统与外部参与者交互的完整功能单元，表示系统提供的可观察的有价值结果。

**Русский:** Прецедент описывает полный функциональный блок взаимодействия системы с внешними актёрами, представляющий наблюдаемый и ценный результат для пользователя.

### 用例图组成 / Состав диаграммы прецедентов:

```
┌─────────────────────────────────────────────┐
│                                             │
│    ┌─────┐         ┌──────────┐            │
│    │:Actor│◄──────►│ (UseCase)│            │
│    │ 参与者 │ 关联   │   用例    │            │
│    └──┬──┘         └────┬─────┘            │
│       │                 │                   │
│       │    ┌────────────┘                   │
│       │    │ include («включает»)           │
│       │    ▼                                │
│       │  ┌──────────┐                       │
│       └──┤(UseCase2)│                       │
│          │  用例2   │                       │
│          └──────────┘                       │
│                                             │
└─────────────────────────────────────────────┘
```

### 核心元素 / Основные элементы:

| 元素 / Элемент                              | 表示 / Обозначение     | 说明 / Описание                                                                                                                         |
| -------------------------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **参与者 / Актёр**                      | 小人图标 / Человечек 👤  | 与系统交互的人、组织或其他系统 / Люди, организации или системы, взаимодействующие с системой |
| **用例 / Прецедент**                | 椭圆 / Овал                   | 系统功能单元 / Функциональный блок системы                                                                             |
| **系统边界 / Граница системы** | 矩形 / Прямоугольник | 定义系统范围 / Определяет границы системы                                                                               |

### 关系类型 / Виды связей:

#### 1. 关联关系 / Ассоциация (Association)

**中文：** 参与者与用例之间的通信连接，表示参与者使用用例功能。

**Русский:** Связь коммуникации между актёром и прецедентом, показывающая использование функции.

```
Актёр ──────────► (Прецедент)
```

#### 2. 包含关系 / Включение (Include) ⭐

**中文：** 一个用例必须调用另一个用例的功能，是强制性的公共行为提取。

**Русский:** Один прецедент обязательно вызывает функциональность другого, обязательное извлечение общего поведения.

```
(Базовый прецедент) ──►(include)──► (Включённый прецедент)
      基础用例          «включает»        被包含用例
```

**示例 / Пример:**

- "下订单" 包含 "验证用户身份" / "Оформить заказ" включает "Проверить подлинность пользователя"

#### 3. 扩展关系 / Расширение (Extend) ⭐

**中文：** 在特定条件下向基础用例添加可选行为，是条件性的功能扩展。

**Русский:** Добавление опционального поведения к базовому прецеденту при определённых условиях, условное расширение.

```
(Расширяющий прецедент) ◄──(extend)── (Базовый прецедент)
      扩展用例            «расширяет»       基础用例
                              │
                         [условие расширения]
                          扩展条件
```

**示例 / Пример:**

- "下订单" 被 "使用优惠券" 扩展（当用户有优惠券时）/ "Оформить заказ" расширяется "Применить купон" (если у пользователя есть купон)

#### 4. 泛化关系 / Обобщение (Generalization)

**中文：** 参与者或用例之间的继承关系，子元素继承父元素特性并可添加新特性。

**Русский:** Отношение наследования между актёрами или прецедентами, дочерний элемент наследует свойства родителя.

```
    ┌─────────────┐
    │  (Родитель) │  父用例/参与者
    │   父用例    │
    └──────┬──────┘
           △
          / \
    ┌────┘   └────┐
    │             │
(Потомок 1)   (Потомок 2)  子用例/参与者
  子用例1        子用例2
```

**示例 / Пример:**

- 参与者："用户" ← "注册用户", "管理员" / Актёры: "Пользователь" ← "Зарегистрированный пользователь", "Администратор"

### 关系对比 / Сравнение отношений:

| 关系 / Отношение             | 方向 / Направление                | 强制性 / Обязательность              | 使用场景 / Сценарий использования                              |
| ------------------------------------- | -------------------------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **关联 / Ассоциация** | 双向 / Двунаправленное        | 必须 / Обязательно                      | 参与者使用用例 / Актёр использует прецедент                 |
| **包含 / Include**              | 指向被包含者 / К включаемому     | 总是执行 / Всегда выполняется     | 提取公共行为 / Извлечение общего поведения                 |
| **扩展 / Extend**               | 从扩展者指出 / От расширяющего | 条件执行 / Условное выполнение   | 可选功能分支 / Опциональные ветви функциональности |
| **泛化 / Generalization**       | 指向父类 / К родителю               | 继承特性 / Наследование свойств | 分类层次结构 / Иерархия классификации                          |
