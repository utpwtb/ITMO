为 Gradle + Groovy 编写一个构建脚本，实现对《Web 编程》课程第 3 号实验项目代码的编译、测试并打包成 war归档文件。

每个阶段应划分为脚本中一个独立的块；脚本中使用的所有变量和常量应提取到单独的属性文件中；MANIFEST.MF 文件应包含版本信息和启动类信息。

脚本应实现以下目标：

* **compile** -- 编译项目的源代码。
* **build** -- 编译项目源代码并将其打包成war 归档文件。源代码的编译通过调用 compile 目标来实现。
* **clean** -- 删除项目已编译的类文件及所有临时文件（如果有的话）。
* **test** -- 运行项目的 JUnit 测试。在运行测试之前，必须先构建项目（build 目标）。
* **xml** -- 验证项目中所有的 XML 文件。
* **scp** -- 构建完成后，通过 SCP 将构建好的项目传送到选定的服务器上。必须先执行项目构建（build 目标）。
* **native2ascii** -- 对本地化文件的副本执行 native2ascii 转换（为测试脚本，所有字符串参数必须从类中提取到本地化文件中）。
* **music** -- 构建完成后（build 目标）播放音乐。
* **doc** -- 在 MANIFEST.MF 文件中添加项目文件的 MD5 和 SHA-1 摘要，并为项目中的所有类生成 Javadoc 文档并将其添加到归档文件中。
* **history** -- 如果项目编译失败（compile 目标），则从 SVN 仓库加载上一个版本。重复此操作，直到项目构建成功，或者已获取到仓库中最旧的修订版。如果找到了能成功构建的修订版，则创建一个文件，其中包含对紧随最后一个可工作修订版之后的那个修订版中所有更改文件的 diff 操作结果。
* **team** -- 从 Git 仓库中获取前两个修订版，构建它们（与主项目构建方式类似）并将生成的 jar 文件打包成 zip 归档文件。构建过程通过调用 build 目标来实现。
* **alt** -- 创建一个修改变量和类名的替代版本程序（在属性文件中使用 replace/replaceregexp 任务定义）并将其打包成 jar 归档文件。使用 build 目标来创建 jar 归档文件。
* **report** -- 如果测试成功通过，则以 XML 格式保存 JUnit 报告，将其添加到 SVN 仓库并执行提交。
* **env** -- 在替代环境中构建和运行程序；环境由属性文件中指定的 Java 版本和虚拟机参数集定义。
* **diff** -- 检查工作副本的状态，如果更改不涉及属性文件中指定的类，则在 SVN 仓库中执行提交。

实验作业答辩问题：

1. 软件测试。测试目的，测试类型。
2. 单元测试，基本原理和使用的方法。
3. JUnit 包，基本 API。
4. 自动构建系统。用途，工作原理，系统示例。
5. Make 工具。Make 文件，目标和规则。
6. Ant 工具。构建脚本，目标和命令。
