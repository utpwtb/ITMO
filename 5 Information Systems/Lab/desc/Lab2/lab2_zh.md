# 对实验一信息系统的扩展要求

按照以下要求对实验一（ЛР1）开发的信息系统进行扩展：

1. **在系统中增加通过导入文件批量添加对象的功能。** 导入文件的格式需要与教师协商确定。导入文件必须通过已开发的 Web 应用界面上传到服务器。
   - 实现对象导入逻辑时，必须使用事务，确保导入过程中一旦发生错误，就不会创建任何对象（整个导入操作回滚）。
   - 导入时必须按照实验一中业务领域的约束条件，对用户输入的数据进行校验。
   - 如果实验一中的主要对象包含嵌套对象，那么嵌套对象各字段的值必须与主要对象写在同一条记录中。

2. **为系统添加导入历史记录的展示界面。** 普通用户只能查看自己发起的导入操作，管理员可以查看所有导入操作。
   - 历史记录中必须显示：操作 ID、操作完成状态、发起操作的用户，以及本次操作添加的对象数量（仅对成功完成的操作显示数量）。

3. **与教师协商，并在实验一的数据模型中增加新的唯一性约束，通过程序进行检查。** 这些新的唯一性约束必须在应用程序的业务逻辑层实现，不得在数据库中体现或实现。

4. **使用 Apache JMeter 实现一个模拟多个用户同时操作信息系统的测试场景，** 检查实验中使用的事务隔离机制是否正确。根据对系统在多用户并发使用情况下的行为分析，在必要的地方调整事务隔离级别，并说明调整的理由。
   - 测试场景必须覆盖对象的创建、编辑、删除和导入操作。
   - 测试场景必须验证：当多个用户尝试更新和/或删除同一个对象时（例如两名管理员），系统能否正确处理。
   - 测试场景必须验证：当多个用户同时尝试创建具有相同唯一字段值的对象时，系统能否正确遵守业务领域的唯一性约束。

## 实验答辩问题

1. 软件系统中业务逻辑的概念；业务逻辑层在多层软件架构中的位置和作用。
2. Jakarta Enterprise Beans（EJB）：Bean 的类型及其用途。
3. EJB Session Beans（会话 Bean）：生命周期。
4. 事务的概念；数据库事务；ACID 特性。
5. 多用户并发操作数据时的冲突类型；事务隔离级别。
6. 在业务逻辑层实现事务的特点，以及它与数据库层事务的区别。
7. Java Transaction API（JTA）：基本原则和编程接口。
8. Jakarta EE 中的事务管理实现；声明式事务管理与编程式事务管理。
9. Spring 中的事务管理实现；Spring 的声明式事务管理与编程式事务管理；`@Transactional` 注解。
