# Лабораторная работа № 1, вариант 4101

Информационная система управления фильмами: Jakarta EE 10 (CDI managed beans, REST, Bean Validation), EclipseLink 4.0.5, PostgreSQL 17. Java 17+, Maven 3.9+. Проверенная среда: Java 21, PostgreSQL 17.4, Payara Micro 6.2025.1. JUnit использует EclipseLink 4.0.5 из Maven. В Payara действует родительская загрузка классов: контейнерный EclipseLink 4.0.1.payara-p3 (подтверждено JVM classloaders и JAR manifest); браузерные проверки выполнены на нём.

## Быстрый запуск в Windows

Установите JDK 17+ и Maven (команды `java` и `mvn` в PATH), PostgreSQL 17. Из корня проекта:

```powershell
./scripts/start-local.ps1
```

Скрипт создаёт собственный кластер `.runtime/pgdata`, базы `movie_lab` и `movie_lab_test`, применяет схему только к новой базе, выполняет тесты и запускает приложение. По умолчанию PostgreSQL слушает **127.0.0.1:55441**, HTTP — **18081**. Если эти порты заняты, используйте `-DatabasePort 55442 -HttpPort 18082`. Не направляйте скрипт на чужой кластер. Локальный кластер использует `trust` только на loopback; он предназначен для лабораторной разработки.

Откройте <http://localhost:18081/movie-lab/>. Учебная учётная запись: **student / student**. Переменные `MOVIE_USER` и `MOVIE_PASSWORD` заменяют её. Несколько независимых сессий могут войти с этой учётной записью. Регистрация и разграничение прав вариантом не предусмотрены. Для проверки синхронизации откройте второй профиль/приватное окно браузера.

Остановка приложения: Ctrl+C. Остановка собственного кластера:

```powershell
& 'C:/Program Files/PostgreSQL/17/bin/pg_ctl.exe' -D .runtime/pgdata stop -m fast
```

## Docker (альтернативная конфигурация)

```sh
docker compose up --build
```

Адрес: <http://localhost:8080/movie-lab/>. Учётная запись та же. Конфигурация Docker предоставлена как альтернативный способ; в этой работе проверен непосредственный запуск Payara/PostgreSQL, поскольку Docker Engine не был запущен. Не используйте `docker compose down -v`, если нужны сохранённые данные.

## Кафедральный PostgreSQL

Создайте отдельную схему в базе `studs`, выполните в ней `database/schema.sql`. Используйте реальный кафедральный логин/пароль через переменные окружения (не сохраняйте пароль в репозитории):

```powershell
$env:MOVIE_DB_URL='jdbc:postgresql://pg:5432/studs?currentSchema=movie_lab'
$env:MOVIE_DB_USER='<кафедральный логин>'
$env:MOVIE_DB_PASSWORD='<кафедральный пароль>'
java -jar payara-micro-6.2025.1.jar --deploy target/movie-lab.war --noCluster
```

Хост `pg` доступен в сети кафедры. Доступ к нему в этой проверке не использовался. Не запускайте `start-local.ps1` для кафедральной БД: скрипт предназначен именно для локального стенда.

## Функции и правила

- Отдельные диалоги создания, просмотра, изменения и удаления; данные связанных объектов раскрываются в просмотре.
- Фильм имеет 16 предметных атрибутов; каждый представлен своей колонкой. `version` — технический счётчик конкурентных изменений.
- Пагинация выполняется на сервере для фильмов. Фильтрация строковых колонок (`name`, `tagline`, названия участников; дополнительно жанр и MPAA) — только полное совпадение, с учётом регистра. Пустую строку можно фильтровать, включив флажок «Включить фильтр».
- Для создания фильма сначала создайте координаты; при необходимости создайте место и человека. В форме фильма выберите существующие объекты по ID. Один человек может участвовать в нескольких ролях и фильмах.
- Удаление координат/человека удаляет зависимые фильмы; удаление места — зависимых людей и их фильмы. Удаление фильма не уничтожает общие справочные объекты. Это направленная каскадная зависимость, реализованная бизнес-логикой и FK `ON DELETE CASCADE`.
- Каждая транзакция изменения блокирует одну строку `app_state`; её ревизия обновляется в той же транзакции. Клиенты проверяют ревизию каждые 2 секунды. Кэш EclipseLink между запросами отключён. Несохранённый ввод не перезаписывается, устаревшее сохранение возвращает HTTP 409.
- `Long` передаётся клиенту десятичной строкой: JavaScript не теряет точность бюджета до `9223372036854775807`.
- `birthday` хранится в ISO ZonedDateTime, включая исходную зону, через JPA converter. БД проверяет формат и календарную корректность. `Country` присутствует как enum из задания, но ни одно поле варианта на него не ссылается.
- Все изменения выполняются на сервере с Bean Validation; ограничения `NOT NULL`, `CHECK`, `UNIQUE`, FK и identity повторяют правила в PostgreSQL.

### Специальные операции

1. Удаление всех фильмов с заданным `usaBoxOffice`.
2. Среднее `usaBoxOffice`; для пустой коллекции `null`, в UI «нет данных».
3. Массив фильмов с буквальным префиксом `tagline`; `%`, `_`, `!` экранируются; пустой префикс возвращает всю коллекцию.
4. Перераспределение наград: **по согласованному уточнению** каждый фильм исходного жанра сохраняет 1 «Оскар», остальные переходят целевому жанру. Это устраняет противоречие исходного текста с `oscarsCount > 0`. Разные непустые жанры обязательны. Квота `q = S / n`, остаток `r = S % n`, первые `r` фильмов по ID получают на 1 больше. Сумма наград сохраняется; равны добавки, а не итоговые значения с учётом прежних наград.
5. Добавление положительного числа наград фильмам с `length > порога`. Переполнение int в операциях 4/5 отменяет всю транзакцию.

Алгоритмы находятся в `MovieService`, хранимые процедуры/функции для бизнес-операций не используются. Простой агрегат AVG вычисляется JPQL-запросом сервиса, остальные изменения — через управляемые сущности.

## Проверка

Создайте отдельную БД `movie_lab_test` для доступного пользователя и выполните:

```powershell
mvn '-DMOVIE_TEST_DB_URL=jdbc:postgresql://127.0.0.1:55441/movie_lab_test' verify
```

JUnit создаёт уникальную временную схему, применяет настоящий PostgreSQL DDL и удаляет только эту схему после тестов. H2 и mock ORM не используются. JDBC user/password задаются системными свойствами `-DMOVIE_DB_USER=...`, `-DMOVIE_DB_PASSWORD=...`. Для браузерной проверки нужен Node.js и Playwright:

```sh
npm install --no-save playwright
node scripts/browser-test.cjs
```

Скрипт рассчитан на установленный Chrome Windows; `CHROME_PATH`, `MOVIE_BASE_URL`, `PLAYWRIGHT_MODULE` позволяют изменить пути. Он запускает два независимых браузерных контекста, проверяет CRUD-синхронизацию, конфликт версий, вход, CSRF, подробности и специальные операции. Протокол сохраняется в соседний `verification/`. После успешного выполнения тестовые фильм и координаты удаляются.

## Архитектура и исходники

`domain` — JPA-сущности, enum, конвертеры; `persistence` — EntityManagerFactory и транзакции; `service` — проверки и алгоритмы; `web` — CDI-ресурсы REST, сессии, CSRF и обработка ошибок; `src/main/webapp` — русский интерфейс. Полный исходный код включён в поставку; удалённый репозиторий не создавался.

Встроенная учётная запись, единая блокировка записей, опрос и загрузка целых справочников — осознанные упрощения учебной системы. В промышленной версии потребуются полноценные пользователи, HTTPS, ограничение попыток входа, миграции схемы и более масштабируемая доставка событий.
