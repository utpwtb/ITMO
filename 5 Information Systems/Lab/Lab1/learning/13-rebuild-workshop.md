# 13 如果让我从空目录独立重写，应该怎么推进

本章给出重建顺序和验收点。它是学习练习，不代表要删除当前完成的项目。建议在你自己的新目录中实现，每次只新增一种你能够解释的能力。

## 阶段 1：先让 Web 请求抵达 Java

建立 Maven WAR 项目，声明 Jakarta API；创建一个最小 REST Application 和 GET 接口，在 Payara 中部署。

教学示意：

```java
@Path("hello")
public class HelloResource {
    @GET
    @Produces("text/plain")
    public String hello() { return "Hello"; }
}
```

它还需要注册到 Application，不能只把类放到任意目录就假定能访问。

**验收：** 浏览器访问你实际配置的路径得到文本。说清每段 URL 从哪里来，辨认 404 是路由、部署路径还是应用未启动的问题。

## 阶段 2：先学一个最简单的实体

先实现 Coordinates，而不是一次把整个 Movie 全写完。建立带 identity、x、y、version 的表，写 JPA 实体和持久化单元。

再写数据库组件，明确工厂与管理器的生命周期。暂时用一个独立 Java/JUnit 调用验证能连接数据库并插入坐标。

**验收：** 合法 x=826 成功，x=827 被拒绝，NULL y 被拒绝；直接 SQL 也不能绕过数据库约束。

## 阶段 3：先写具体保存逻辑，再考虑通用反射

初学者可以先编写 `createCoordinates(Integer x,Integer y)`：赋值、验证、persist、提交。不必第一天就复制当前 `save(kind,id,input)` 的反射实现。

理解具体字段之后，再思考四种对象共有的流程：资源类型选择、字段解析、关联查找、校验、保存。只有确实理解这些共同点，抽象才有意义。

**验收：** 能在纸上指出哪一行发生类型转换、哪一行写数据库、哪一行提交事务。

## 阶段 4：加入 Movie 和引用

增加电影实体和表，先只完成创建与按 ID 读取；请求传坐标 ID，服务层按 ID 查坐标。

如果引用不存在，返回明确错误；不要悄悄创建一条新坐标，也不要只把 ID 拼进任意 SQL。

**验收：** 两部电影复用同一坐标；重启应用后仍能读取；创建日期来自数据库，浏览器无法手动覆盖。

## 阶段 5：让最简单的页面消费接口

先写一个读取列表按钮与静态表格，再添加创建弹窗。浏览器 Network 面板能看到真实请求与结果。

这一阶段先把一种实体的完整链路跑通：输入 → JSON → Java → SQL → Java → JSON → 页面。确认后再扩展人员、地点、枚举与动态表单。

**验收：** 不看服务器日志也能在页面看见字段错误；错误保存时输入不被清空。

## 阶段 6：加入修改、删除和查询规则

实现按 ID 修改，携带旧 version；加入表格分页与精确筛选；实现辅助对象的方向性级联删除。

先准备一张“谁引用谁”的图再写删除代码。特别测共享人员：删一部电影不能误删另一部共用同一人员的电影。

**验收：** 同名数据翻页顺序稳定；精确过滤不变成前缀匹配；空关联对象不会因排序丢失；删除后超出页码能回退。

## 阶段 7：增加特殊操作与事务失败场景

按照第 09 章实现五个操作。奖项操作先用 long 算中间结果，再检查 int 上限。为空、余数、同一类型、无匹配记录都要有明确结果。

**验收：** 来源 `[5,4]` 与目标 `[2,2]` 转移后是 `[1,1]` 与 `[6,5]`；任意电影溢出时其他电影不发生部分提交。

## 阶段 8：增加会话、并发控制和同步

用 Session 维护登录状态，给修改操作加 CSRF 校验。所有业务写入遵守同一个事务协调入口；旧表单使用对象 version；页面用全局 revision 判断是否刷新。

可以分三次验证：先拒绝未登录请求；再验证旧版本冲突；最后开两个独立浏览器上下文验证自动同步。

**验收：** 两个同时加奖的请求都被保留；有旧表单的人收到冲突提示；另一客户端不用手动刷新就看到提交结果。

## 阶段 9：让启动和测试可复现

把依赖、端口、数据库初始化、构建、部署写成可读脚本。测试使用独立数据库/schema，运行后输出结果。测试日志应说明何时运行、测试什么，而不是只留一张绿色截图。

**验收：** 换一个空测试 schema 仍能运行；不依赖之前手工创建但未记录的表；没有把密码写进提交代码。

## 四个定向练习及判断标准

| 练习 | 改动范围 | 成功标准 |
|---|---|---|
| 让默认页大小为 20 | REST 默认值、前端初值/下拉框 | 无参数请求和页面默认一致 |
| 增加按 MPAA 精确过滤的用例 | 测试 | PG 不匹配 PG_13 |
| 检查摄像师删除级联 | 人员与电影测试 | 只通过 operator 引用的电影也被删除 |
| 给接口写字段错误 DTO 设计草图 | API/服务设计文档 | 能关联字段名与多个错误，不丢失 HTTP 状态 |

前三项当前功能可能已有部分支持，练习重点是找到正确修改点和证明行为。第四项是设计练习，当前版本仍使用错误字符串，不要把你的草图当作已经实现。

## 完成标志

能不看教程画出一次保存的链路，解释每个框架解决的问题，并能故意构造一个错误后预测它会在哪一层被拒绝。这比逐字背诵一个服务类更接近真正掌握。
