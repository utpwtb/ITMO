# JSON-импорт фильмов

Загрузите UTF-8 файл с расширением .json через страницу «Импорт». Размер — не более 5 MiB, число фильмов — от 1 до 1000. Начальный UTF-8 BOM допустим. Комментарии, завершающие запятые, повторные и неизвестные свойства запрещены. При ошибке не сохраняется ни один фильм и ни один новый вложенный объект.

## Структура

```json
{
  "formatVersion": 1,
  "movies": [{
    "name": "Пример",
    "coordinates": {"x": 100, "y": -20},
    "oscarsCount": 1,
    "budget": "9007199254740993",
    "totalBoxOffice": null,
    "mpaaRating": "PG_13",
    "director": null,
    "screenwriter": null,
    "operator": null,
    "length": 120,
    "goldenPalmCount": null,
    "usaBoxOffice": 1,
    "tagline": "",
    "genre": "COMEDY"
  }]
}
```

Полный пример с вложенными объектами: [import-valid.json](examples/import-valid.json).

Верхний объект содержит только formatVersion и movies. formatVersion — целое 1, movies — непустой массив. id, version, creationDate, userId, directorId и другие ссылки вместо вложенных значений не принимаются. Генерируемые поля задаёт сервер. Пропущенное необязательное поле эквивалентно null; обязательное нельзя пропустить или заменить null.

## Поля Movie

| Поле | Допустимое значение |
|---|---|
| name | Обязательная непустая строка. Регистр и пробелы сохраняются |
| coordinates | Обязательный вложенный Coordinates |
| oscarsCount | Обязательное 32-битное целое > 0 |
| budget | Обязательное 64-битное целое > 0; рекомендуется десятичная строка |
| totalBoxOffice | null либо конечное число > 0 |
| mpaaRating | Обязательно: G, PG, PG_13, R, NC_17 |
| director, screenwriter, operator | null либо полный вложенный Person |
| length | Обязательное 32-битное целое > 0 |
| goldenPalmCount | null либо 64-битное целое > 0 |
| usaBoxOffice | Обязательное 32-битное целое > 0; не больше totalBoxOffice, когда оно задано |
| tagline | Обязательная строка; пустая допустима |
| genre | null либо WESTERN, COMEDY, TRAGEDY, HORROR |

## Вложенные объекты

| Объект / поле | Допустимое значение |
|---|---|
| Coordinates.x | Обязательное 32-битное целое ≤ 826; отрицательное допустимо |
| Coordinates.y | Обязательное 32-битное целое; отрицательное допустимо |
| Person.name | Обязательная непустая строка |
| Person.birthday | Обязательная строка ZonedDateTime со смещением или часовым поясом, например 1980-01-02T12:00:00+03:00 |
| Person.passportID | Обязательная строка, уникальность паспорта сохранена. Пустая строка не запрещена прежней моделью |
| Person.eyeColor / hairColor | null либо GREEN, BLACK, ORANGE, WHITE, BROWN |
| Person.height / weight | null либо конечный положительный float; после преобразования значение также должно оставаться > 0 |
| Person.location | null либо полный вложенный Location |
| Location.x | Обязательное 64-битное целое; отрицательное допустимо |
| Location.y | Обязательное конечное число double; отрицательное допустимо |
| Location.name | Обязательная строка; пустая допустима |

Целые 32-битные поля принимают только JSON integer в диапазоне от -2147483648 до 2147483647. Дробные значения, true/false и строки для них запрещены. Поля Long принимают JSON integer или десятичную строку без пробелов, дробной части и знака плюс; диапазон от -9223372036854775808 до 9223372036854775807. Преобразование точное: превышение диапазона отклоняется. Для double/float требуется JSON number; NaN, Infinity, переполнение и недопустимое уменьшение float до нуля отклоняются.

## Создание и повторное использование

Для каждого фильма создаётся новый Coordinates. Person определяется passportID: отсутствующий создаётся вместе с Location, существующий используется только при совпадении всех входных данных. Расхождение имени, дня рождения, часового пояса, цвета, роста, веса или местоположения вызывает PERSON_DATA_CONFLICT и откат всего файла. Импорт не перезаписывает существующих людей. Повторные вхождения одного паспорта внутри файла должны описывать одного и того же человека. Пропуск nullable-полей и null эквивалентны; дата сравнивается после разбора с сохранением идентичности часового пояса, Location — по значениям полей.

Уникален точный набор (name фильма, идентификатор Person режиссёра либо null). Люди с одинаковыми именами и разными паспортами могут быть разными режиссёрами. Два одинаковых названия без режиссёра конфликтуют. Изменение имени или паспорта сохранённого человека не меняет его идентификатор. Собственный ключ при редактировании не считается дубликатом. Дубликат внутри файла, повторная загрузка и конфликт с БД приводят к отказу всего файла: пропуск и обновление существующего фильма не выполняются.

## Результат и история

Операция отображается в истории как RUNNING, SUCCESS или FAILED. Только SUCCESS показывает фактическое число добавленных Movie. FAILED и RUNNING показывают «—». Обычный пользователь видит свои операции; администратор — все.

При отказе сохраняются код, номер записи и путь, например movies[1].director. DUPLICATE_MOVIE и PERSON_DATA_CONFLICT возвращаются с 409; неверный JSON/поле — 400; нет входа — 401; неверный CSRF — 403; чужая история — 404; превышение размера — 413; неподдерживаемый тип — 415. Временная проблема БД/ожидание блокировки — 503, неожиданная внутренняя ошибка — 500.

Принятая загрузка создаёт историю до разбора JSON, поэтому синтаксическая ошибка оставляет FAILED. Неаутентифицированный запрос, отсутствие/пустота файла, неверный тип и превышение размера отвергаются до создания истории. Если исход commit неизвестен, сохраните operationId и проверьте историю; автоматически повторно отправлять файл нельзя.

Для программного клиента: POST /api/imports, multipart/form-data, поле file, тип file part application/json, Session Cookie и X-CSRF-Token. Браузер сам устанавливает boundary; передавайте исходный File без JSON.parse/JSON.stringify, чтобы сохранить большие целые.
