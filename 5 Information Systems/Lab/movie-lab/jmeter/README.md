# Конкурентная проверка лабораторной работы № 2

Фактические результаты находятся в `../../verification/Lab2/`. JMX содержит HTTP Cookie Manager с отдельным сеансом каждого потока, вход с извлечением CSRF, предварительное чтение версии, Synchronizing Timer с ограничением 20 секунд и дополнительный CyclicBarrier с ошибкой при неполном составе. CRUD и multipart проходят одну точку синхронизации. У multipart нет JSON Content-Type Header Manager: boundary формирует JMeter, имя file part — `file`, тип — `application/json`.

`lab2-concurrency.jmx` редактируется в JMeter GUI; генератор `../scripts/build-lab2-jmx.py` воспроизводит ту же структуру. Groovy-файлы обслуживают подготовку и проверку, HTTP выполняют нативные HTTP Request samplers. `scenario`, `threads`, `rounds`, `host`, `port`, `basePath`, `fixtureFile`, `resultFile` подключены к плану.

## Запуск на Helios

1. Остановить интеграционные тесты и запустить кандидата через `python3.11 scripts/helios.py start-test` на изолированных `lab2_4101_test_` таблицах.
2. `python3.11 scripts/lab2-functional.py accounts` создаёт два обычных аккаунта и два административных. Случайные пароли сохраняются только в `.runtime/lab2-users.json` с правами 0600. SSH-пароль для них не используется.
3. Установить официальный Apache JMeter 5.6.3 в `tools/apache-jmeter-5.6.3` (дистрибутив из Apache archive). Java: `/usr/local/openjdk21`; HEAP: `-Xms64m -Xmx256m`.
4. Из корня проекта: `python3.11 scripts/lab2-jmeter.py verification/Lab2/<new-run-id>`. По умолчанию все 13 вариантов C01–C12, 20 раундов, 2 потока для двухсторонних гонок и 10 для остальных. C02D — отдельная гонка delete/delete. Для короткой отладки: `JMETER_ROUNDS=2 python3.11 scripts/lab2-jmeter.py verification/Lab2/<pilot> C03`.

Генератор подготавливает объекты через API, заранее фиксирует общие ключи и версии каждого раунда. У каждого потока отдельная авторизация. Файлы сценариев не содержат паролей/токенов. Каждый импорт передаёт настоящий файл. Все запросы создаются на Helios и направлены на `127.0.0.1:40797/movie-lab/api`.

Сохранены `command.json`, fixture JSON, `responses.jsonl`, `results.jtl`, `jmeter.log`, HTML dashboard, снимки БД и `assertions.json`. Код возврата 0 от JMeter недостаточен: Python проверяет JTL, точные числа победителей/конфликтов, версии/значения, атомарность импорта, четыре типа объектов, устойчивую историю, отсутствие дубликатов и висячих ссылок. При любой ошибке возвращается ненулевой код. Ожидаемый 409 считается успехом только при правильном коде и конечном состоянии. Любой непредусмотренный 5xx, сетевой сбой или таймаут барьера остаётся ошибкой.

## Контролируемое сравнение изоляции

После остановки кандидата `scripts/lab2-test-state.py backup` сохраняет частный дамп ровно семи тестовых таблиц в `.runtime/comparison-baseline.dump`. Восстановление `restore` запрещено при работающем процессе кандидата и затрагивает только эти таблицы. Перед каждой сравниваемой группой восстанавливается один дамп. Дамп с учётными записями не входит в отчёт или исходный архив.

Один WAR и одинаковый AppState lock используются при `MOVIE_ISOLATION='READ COMMITTED'` и `MOVIE_ISOLATION=SERIALIZABLE`; настройки наследует `helios.py start-test`. Повторы 40001 ограничены тремя и записываются в серверный журнал. Не следует повышать число повторов после просмотра результатов, чтобы скрыть нестабильность. Окончательное решение и ограничения приводятся в `../../verification/Lab2/isolation-analysis.md`.
